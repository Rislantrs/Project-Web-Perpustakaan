Buku Panduan Komprehensif:
Basis Data, Storage, dan Migrasi

Panduan teknis lengkap integrasi React frontend dengan database lokal (MySQL) atau Cloud (Supabase/PostgreSQL) beserta penanganan file storage dan cron job.

Diperbarui: Juni 2026 | Disusun oleh: M. Rislan Tristansyah (Mahasiswa Sistem Telekomunikasi)

Bab 1: Panduan Migrasi Database Kustom

Bab ini disusun khusus sebagai acuan utama dalam memindahkan, mengadaptasi, dan mengoperasikan sistem basis data website Disipusda dari infrastruktur cloud Supabase (PostgreSQL) ke basis data relasional MySQL tradisional di lingkungan hosting umum (seperti cPanel, VPS, Hostinger, atau server dinas lokal).

1. Perbandingan Paradigma Fundamental: PostgreSQL vs MySQL

Sebelum memulai migrasi, Anda wajib memahami perbedaan arsitektur di bawah ini agar tidak terjadi kesalahan logika saat query database dijalankan:

Fitur / Karakteristik Supabase (PostgreSQL) MySQL (cPanel / Hosting Umum) Solusi Transisi / Migrasi
UUID (Universally Unique ID) Didukung secara natif (uuid). Nilai acak 36 karakter. Tipe data UUID tidak didukung secara natif (sebelum MySQL 8.0). Gunakan tipe VARCHAR(36) di MySQL. Ini aman karena UUID dapat disimpan sebagai string.
Row Level Security (RLS) Keamanan baris data dikontrol di tingkat DB lewat SQL Policies. Tidak mendukung RLS di tingkat database. Pindahkan validasi otorisasi penuh ke tingkat aplikasi backend (skrip PHP/Node.js).
Data Dokumen JSON Tipe data JSONB yang mendukung indexing b-tree cepat. Tipe JSON (MySQL 5.7.8+) atau fallback ke tipe TEXT. Gunakan kolom TEXT di MySQL, dan parse string JSON menjadi object di backend.
Timestamp & Zona Waktu Tipe TIMESTAMPTZ yang menyimpan zona waktu akurat (UTC). Tipe DATETIME atau TIMESTAMP lokal. Simpan data waktu dalam format UTC atau set database timezone secara global ke GMT+7 (SET time_zone = '+07:00').
Bahasa Pemrograman DB Prosedur tersimpan menggunakan PL/pgSQL. Prosedur tersimpan menggunakan standard SQL/PSM. Tulis ulang fungsi/prosedur database (seperti RPC) menjadi query native di backend.

2. Pemetaan Tipe Data & Kompatibilitas Sistem

Gunkan pemetaan (mapping) tipe data berikut saat mengkonversi struktur tabel dari PostgreSQL ke MySQL:

  • UUID ➡️ VARCHAR(36)
  • TIMESTAMPTZ ➡️ DATETIME (atau TIMESTAMP dengan default CURRENT_TIMESTAMP)
  • TEXT (panjang tak terbatas) ➡️ TEXT atau LONGTEXT
  • JSONB ➡️ JSON (atau TEXT jika MySQL di bawah versi 5.7)
  • BOOLEAN ➡️ TINYINT(1) (di mana 1 = true dan 0 = false)
  • BIGSERIAL (Auto-Increment) ➡️ BIGINT UNSIGNED AUTO_INCREMENT

3. Opsi Migrasi A: Ekspor/Impor CSV Secara Manual (phpMyAdmin & CLI)

Opsi ini sangat cocok jika Anda ingin melakukan migrasi satu kali (one-time migration) untuk memindahkan data statis/historis seperti buku (books), kategori (categories), atau portal berita (articles) dari Supabase ke server hosting MySQL baru Anda.

Langkah 1: Ekspor Data dari Supabase

  1. Masuk ke Dashboard Supabase > pilih proyek Anda.
  2. Buka menu Table Editor di bilah navigasi kiri.
  3. Pilih tabel yang ingin diekspor (contoh: books).
  4. Klik tombol Export to CSV di pojok kanan atas tabel. File CSV akan diunduh ke komputer Anda.

Langkah 2: Persiapkan File CSV & Pembersihan Data

Beberapa kolom timestamp di Supabase berformat ISO 8601 dengan zona waktu UTC (contoh: 2026-06-07T15:30:00Z). MySQL tidak dapat mendeteksi huruf T dan Z secara default.

  1. Buka file CSV menggunakan program text editor modern (seperti Notepad++ atau VS Code).
  2. Format Tanggal: Lakukan Find and Replace: ganti huruf T pada tanggal menjadi satu karakter spasi kosong, dan hapus huruf Z di bagian akhir (ganti dengan string kosong). Format tanggal kini menjadi: YYYY-MM-DD HH:MM:SS.
  3. Konversi UUID ke String: Jika tabel Anda menggunakan UUID (seperti id buku atau member), pastikan kolom tersebut terisi string 36-karakter acak. MySQL akan menyimpannya sebagai VARCHAR(36).
  4. Encoding File: Simpan kembali berkas dengan format .csv menggunakan encoding UTF-8 agar karakter khusus tidak rusak.

Langkah 3: Impor ke MySQL

Metode 1: Melalui phpMyAdmin (Untuk Ukuran File < 10MB)

  1. Masuk ke cPanel/hPanel > buka **phpMyAdmin**.
  2. Pilih database tujuan Anda di bilah sisi kiri, dan pastikan struktur tabel sudah dibuat terlebih dahulu.
  3. Klik pada tabel tujuan (contoh: books), kemudian masuk ke tab Import di bagian menu atas.
  4. Klik Choose File dan pilih file CSV hasil edit Anda.
  5. Pada opsi konfigurasi format:
    • Pilih format: CSV (atau CSV using LOAD DATA jika server mendukung).
    • Setel Fields terminated by menjadi , (koma).
    • Setel Fields enclosed by menjadi " (tanda kutip ganda).
    • Centang opsi Partial Import (mengizinkan pemisahan query jika script mendekati batas limit waktu eksekusi PHP).
  6. Klik tombol Import di bagian paling bawah.

Metode 2: Melalui Command Line / CLI (Untuk File Besar > 10MB)

Jika file CSV berukuran sangat besar, gunakan perintah SQL LOAD DATA INFILE langsung dari client database (MySQL CLI) atau terminal SSH:

-- Masuk ke MySQL CLI lalu jalankan perintah berikut:
LOAD DATA LOCAL INFILE '/path/ke/file/books.csv'
INTO TABLE disipusda_library.books
FIELDS TERMINATED BY ','
ENCLOSED BY '"'
LINES TERMINATED BY '\n'
IGNORE 1 LINES
(id, judul, penulis, penerbit, sinopsis, stok, rak, sampulUrl, rating, created_at, updated_at);
Peringatan Keamanan Local Infile
Secara default, fitur LOCAL INFILE dinonaktifkan di MySQL untuk alasan keamanan. Anda harus mengaktifkannya terlebih dahulu di sisi client dan server:
- Di server: setel local_infile = ON pada konfigurasi my.cnf.
- Di client: hubungkan dengan perintah mysql --local-infile=1 -u username -p.

4. Opsi Migrasi B: Arsitektur API Bridge (Jembatan Sinkronisasi API)

Jika Anda ingin mempertahankan sistem database lokal milik instansi dan menggunakan website React sebagai tampilan (frontend) saja, Anda wajib menggunakan API Bridge (Jembatan API).

[ React Frontend (Vite) ] │ ▼ (Mengirim Request API HTTP Aman + Bearer Token) [ Backend API Bridge (Hostinger/cPanel) ] │ ▼ (Query Lokal via localhost / 127.0.0.1) [ MySQL Database Lokal (Instansi) ]

6. Skrip Backend Jembatan (PHP & Node.js Express Mandiri)

Di bawah ini adalah kode jembatan API (production-ready) yang tangguh, aman, dan siap dipasang di server Anda.

Opsi A: Skrip API PHP menggunakan PDO (cPanel Shared Hosting)

Simpan berkas ini sebagai api.php di dalam direktori public_html/api/ server hosting Anda:

<?php
// 1. Konfigurasi Header CORS & Keamanan
header("Access-Control-Allow-Origin: *");
header("Content-Type: application/json; charset=UTF-8");
header("Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS");
header("Access-Control-Max-Age: 3600");
header("Access-Control-Allow-Headers: Content-Type, Access-Control-Allow-Headers, Authorization, X-Requested-With");

if ($_SERVER['REQUEST_METHOD'] === 'OPTIONS') {
    http_response_code(200);
    exit();
}

// 2. Autentikasi Token Bearer
$headers = getallheaders();
$authToken = isset($headers['Authorization']) ? str_replace('Bearer ', '', $headers['Authorization']) : '';
$expectedToken = "GANTI_DENGAN_TOKEN_KEAMANAN_RAHASIA_ANDA";

if (empty($authToken) || $authToken !== $expectedToken) {
    http_response_code(401);
    echo json_encode(["success" => false, "message" => "Akses Ditolak: Token tidak sah."]);
    exit();
}

// 3. Konfigurasi Database MySQL (PDO)
$db_host = "localhost";
$db_user = "u12345_pusdauser";
$db_pass = "Password_Kuat_Anda_Di_Sini";
$db_name = "u12345_disipusda";

try {
    $dsn = "mysql:host=$db_host;dbname=$db_name;charset=utf8mb4";
    $options = [
        PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
        PDO::ATTR_EMULATE_PREPARES   => false,
    ];
    $pdo = new PDO($dsn, $db_user, $db_pass, $options);
} catch (\PDOException $e) {
    http_response_code(500);
    echo json_encode(["success" => false, "message" => $e->getMessage()]);
    exit();
}

// 4. Routing logic
$request_uri = $_SERVER['REQUEST_URI'];
$method = $_SERVER['REQUEST_METHOD'];
$path = parse_url($request_uri, PHP_URL_PATH);
$path_parts = explode('/api.php', $path);
$route = end($path_parts);

try {
    if ($route === '/books') {
        if ($method === 'GET') {
            $stmt = $pdo->query("SELECT * FROM books ORDER BY created_at DESC");
            echo json_encode(["success" => true, "data" => $stmt->fetchAll()]);
        }
    }
} catch (\Exception $e) {
    http_response_code(500);
    echo json_encode(["success" => false, "message" => $e->getMessage()]);
}
?>

Bab 2: Panduan Database Lokal Hosting

Menghubungkan React frontend ke database lokal (MySQL/PostgreSQL) yang berada pada hosting yang sama menggunakan perantara server backend jembatan.

1. Konsep Utama: React Sisi Klien vs Sisi Server

ATURAN MUTLAK KEAMANAN
Jangan pernah menulis atau menyimpan kredensial database (Host, Port, Username, Password) di dalam file proyek React/Vite Anda. Semua kode React diunduh secara utuh ke browser pengguna saat mereka mengunjungi situs Anda, sehingga kredensial tersebut dapat dengan mudah dicuri via F12 Developer Tools.

2. Alur Integrasi & Isolasi Kredensial

Semua request dari browser akan dikirim ke API jembatan di server web. Server web bertugas mencocokkan token keamanan, mengambil data dari database lokal menggunakan kredensial rahasia yang terisolasi di server, dan mengirimkan datanya kembali ke browser dalam format JSON.

3. Setup Database Baru di cPanel / hPanel

  1. Masuk ke **Control Panel Hosting** Anda.
  2. Cari menu **MySQL Databases** atau **MySQL Database Wizard**.
  3. Buat database baru (contoh: u12345_disipusda).
  4. Buat user database baru dan password yang kuat, lalu hubungkan user tersebut ke database dengan mencentang **ALL PRIVILEGES**.
  5. Buka menu **phpMyAdmin** dan impor skema tabel yang dibutuhkan ke dalam database tersebut.

4. Skrip Jembatan API PHP PDO

Buat file baru bernama booking_api.php di dalam folder public_html/api/:

<?php
header("Access-Control-Allow-Origin: *");
header("Content-Type: application/json; charset=UTF-8");
header("Access-Control-Allow-Methods: GET, POST, OPTIONS");
header("Access-Control-Allow-Headers: Content-Type, Access-Control-Allow-Headers, Authorization, X-Requested-With");

if ($_SERVER['REQUEST_METHOD'] === 'OPTIONS') {
    http_response_code(200);
    exit();
}

$headers = getallheaders();
$authToken = isset($headers['Authorization']) ? str_replace('Bearer ', '', $headers['Authorization']) : '';
$secureToken = "TOKEN_KEAMANAN_RAHASIA_ANDA";

if (empty($authToken) || $authToken !== $secureToken) {
    http_response_code(403);
    echo json_encode(["success" => false, "message" => "Akses Ditolak!"]);
    exit();
}

// Database Connection
$db_host = "localhost";
$db_user = "u12345_pusdauser";
$db_pass = "Password_Kuat_Anda";
$db_name = "u12345_disipusda";

try {
    $pdo = new PDO("mysql:host=$db_host;dbname=$db_name;charset=utf8mb4", $db_user, $db_pass, [
        PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC
    ]);
} catch (\PDOException $e) {
    http_response_code(500);
    echo json_encode(["success" => false, "message" => "Database Offline"]);
    exit();
}

$method = $_SERVER['REQUEST_METHOD'];

if ($method === 'POST') {
    $input = json_decode(file_get_contents("php://input"), true);
    // Proses simpan booking ke database
    $stmt = $pdo->prepare("INSERT INTO booking_enkapsulasi (id, nama_lengkap, email, whatsapp, tanggal_booking) VALUES (:id, :nama, :email, :wa, :tgl)");
    $stmt->execute([
        ':id' => uniqid('BK-'),
        ':nama' => $input['nama_lengkap'],
        ':email' => $input['email'],
        ':wa' => $input['whatsapp'],
        ':tgl' => $input['tanggal_booking']
    ]);

5. Konfigurasi Rute React Router Fallback (.htaccess cPanel)

Ketika Anda menggunakan rute virtual client-side (seperti /login atau /admin), Apache web server akan mengira alamat tersebut adalah folder fisik di server Anda dan mengembalikan error 404 Not Found saat di-refresh.

Buat berkas bernama .htaccess di folder utama website Anda (public_html/) untuk memaksa semua rute diarahkan ke berkas utama index.html React:

<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /
  
  # Jangan rute ulang jika berkas atau folder fisik benar-benar ada di server
  RewriteCond %{REQUEST_FILENAME} -f [OR]
  RewriteCond %{REQUEST_FILENAME} -d
  RewriteRule ^ - [L]
  
  # Alirkan sisa rute ke file index.html utama React Router
  RewriteRule ^ index.html [L]
</IfModule>

Bab 3: Panduan Skema dan Storage Bucket

Pembagian database per modul fitur serta cara setup penyimpanan file static (storage) yang terhindar dari hardcoding.

1. Pemisahan Skema SQL per Fitur

Modul Fitur Tabel SQL Terkait Fungsi Utama
Portal & Artikel articles, categories, audit_logs Pengelolaan postingan berita, pengumuman, dan kategori berita.
Katalog Perpustakaan books, borrows, queue, members, admins Pengelolaan buku fisik, peminjaman buku, antrean, data member, dan hak akses admin.
Booking Layanan bookings, booking_date_locks, booking_audit_logs Pemesanan kuota layanan harian enkapsulasi arsip dan lock tanggal penuh.

2. Kebijakan RLS (Row Level Security) Supabase Storage

Terapkan kebijakan RLS berikut di dashboard SQL Editor Supabase untuk mengamankan bucket asset gambar:

-- 1. Buat bucket asset jika belum ada
INSERT INTO storage.buckets (id, name, public) 
VALUES ('articles', 'articles', true), ('book-covers', 'book-covers', true)
ON CONFLICT (id) DO NOTHING;

-- 2. Aktifkan RLS
ALTER TABLE storage.objects ENABLE ROW LEVEL SECURITY;

-- 3. Kebijakan Baca Publik
CREATE POLICY "Akses_Publik_Baca" ON storage.objects FOR SELECT TO public
  USING (bucket_id IN ('articles', 'book-covers'));

-- 4. Kebijakan Tulis Hanya Admin
CREATE POLICY "Admin_Bisa_Upload" ON storage.objects FOR INSERT TO authenticated
  WITH CHECK (bucket_id IN ('articles', 'book-covers') AND public.is_admin());

4. Skrip PHP Upload File Aman (Anti-RCE Shell Upload)

Gunakan script ini di server PHP lokal untuk menerima unggahan gambar tanpa resiko serangan shell injector hacker:

<?php
header("Content-Type: application/json");
$authToken = isset(getallheaders()['Authorization']) ? str_replace('Bearer ', '', getallheaders()['Authorization']) : '';

if ($authToken !== "TOKEN_KEAMANAN_RAHASIA") {
    http_response_code(403);
    exit(json_encode(["message" => "Unauthorized"]));
}

if (isset($_FILES['file'])) {
    $file = $_FILES['file'];
    $allowedExt = ['jpg', 'jpeg', 'png', 'webp'];
    $ext = strtolower(pathinfo($file['name'], PATHINFO_EXTENSION));
    
    // Verifikasi mime type asli
    $finfo = finfo_open(FILEINFO_MIME_TYPE);
    $realMime = finfo_file($finfo, $file['tmp_name']);
    
    if (!in_array($ext, $allowedExt) || strpos($realMime, 'image/') !== 0) {
        http_response_code(400);
        exit(json_encode(["message" => "Hanya file gambar yang diperbolehkan!"]));
    }
    
    $newName = uniqid('IMG-', true) . '.' . $ext;
    $uploadDir = 'uploads/';
    
    if (move_uploaded_file($file['tmp_name'], $uploadDir . $newName)) {
        echo json_encode(["success" => true, "url" => "https://domain.com/api/uploads/" . $newName]);
    }
}
?>

5. Skrip Otomatisasi Unduh Backup Supabase Storage

Gunakan script Node.js berikut di komputer lokal Anda untuk mendownload secara massal seluruh file aset gambar dari Supabase Storage:

const { createClient } = require('@supabase/supabase-js');
const fs = require('fs');
const path = require('path');

const supabase = createClient('https://anqopdxzdkpsmtxuultp.supabase.co', 'SERVICE_ROLE_KEY');
const BUCKETS = ['articles', 'book-covers'];

async function downloadFile(bucket, filePath) {
  const { data, error } = await supabase.storage.from(bucket).download(filePath);
  if (error) return console.error(error);
  
  const dest = path.join('./downloaded_assets', bucket, filePath);
  fs.mkdirSync(path.dirname(dest), { recursive: true });
  fs.writeFileSync(dest, Buffer.from(await data.arrayBuffer()));
  console.log(`Unduh: ${bucket}/${filePath}`);
}

Bab 4: Setup Cron Job & Rotasi Cron Secret

Panduan langkah demi langkah mengamankan eksekusi tugas terjadwal (Cron Job) harian.

1. Hubungan CRON_SECRET: Booking & Peminjaman Buku

Kedua modul fitur berada di dalam satu proyek Supabase yang sama, sehingga mereka menggunakan variabel lingkungan (environment variable) keamanan yang sama yaitu CRON_SECRET.

  • Layanan A (Pengingat Buku Pinjaman): Dipicu secara berkala oleh GitHub Actions, mengirim request HTTP ke Supabase Edge Function dengan melampirkan header x-cron-secret.
  • Layanan B (Laporan Booking Harian): Dipicu secara internal oleh ekstensi database pg_cron, mengirim request HTTP internal dengan header x-cron-secret.

2. Panduan Langkah demi Langkah Rotasi Token Keamanan

  1. Jalankan perintah ini di terminal Anda untuk menghasilkan string acak baru: 
    openssl rand -base64 32
  2. Buka dashboard Supabase > **Settings** > **API** > **Secrets**.
  3. Perbarui nilai **CRON_SECRET** dengan string baru tersebut dan simpan.
  4. Buka repo GitHub proyek Anda > **Settings** > **Secrets and variables** > **Actions** > edit secret **`CRON_SECRET`** dengan nilai baru tersebut.
