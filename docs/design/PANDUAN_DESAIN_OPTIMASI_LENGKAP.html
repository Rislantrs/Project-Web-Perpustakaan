Buku Panduan Komprehensif:
Desain UI/UX, Responsivitas & Optimasi Media

Panduan teknis dan daftar perbaikan untuk meningkatkan responsivitas layout mobile (Android), penyelarasan panel admin ramah mobile, serta strategi optimasi aset gambar/media.

Diperbarui: Juni 2026 | Disusun oleh: M. Rislan Tristansyah (Mahasiswa Sistem Telekomunikasi)

Bab 1: Responsivitas UI Global & Layout Utama (Mobile)

Meningkatkan pengalaman pengguna pada resolusi layar handphone yang sempit (seperti Android 360px - 412px) dengan menghindari meluapnya layout ke kanan (horizontal scroll) dan memastikan konten tidak terpotong.

1. Batasan Tinggi Menu Mobile pada Navbar.tsx

Masalah: Menu Mobile Terpotong
Pada perangkat Android dengan layar pendek, daftar navigasi menu mobile yang terbuka (`AnimatePresence`) dapat meluap dan terpotong di bagian bawah, membuat tombol menu bawah tidak dapat di-klik.

Solusi:

  • Tambahkan kelas Tailwind overflow-y-auto max-h-[calc(100vh-80px)] pada panel pembungkus menu mobile. Ini memaksa menu di dalam navbar menjadi scrollable secara vertikal secara mandiri jika melebihi tinggi layar fisik.
  • Pastikan lebar elemen logo di navbar mengecil secara dinamis menggunakan responsive width pada lebar layar sangat sempit (< 320px) agar tombol hamburger menu tidak terdorong keluar kontainer.

2. Penyusunan Kolom di Footer.tsx

Di layar mobile, kolom footer statis berdampingan dipaksa bertumpuk menjadi 1 kolom menggunakan kelas responsive:

className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-8"

Ini mencegah baris tautan teks menjadi sangat sempit, bertumpuk, atau tidak dapat dibaca di layar HP.

Bab 2: Panduan Responsivitas Halaman Publik (Frontend)

Penyelarasan layout pada halaman yang diakses publik agar ramah mobile menggunakan penulisan utility class Tailwind CSS secara proporsional.

1. Judul Utama & Grid Berita (Home.tsx)

  • Responsive Text size: Judul pahlawan utama "Disipusda Purwakarta" diatur menggunakan skala adaptif: 
    className="text-3xl sm:text-5xl lg:text-6xl"
  • Jarak Antara Kolom Berita: Di mobile, grid berita utama (lg:col-span-7) dan berita pendukung (lg:col-span-5) ditumpuk dengan jarak gap vertikal (gap-6) yang cukup agar tidak saling bertabrakan.

2. Tab Switcher & Segmen Grid (Diorama.tsx)

  • Tab Switcher Padding: Tombol toggle tab (Diorama Purwakarta / Nusantara) menggunakan padding responsif: 
    className="px-4 py-2 sm:px-8 sm:py-3"
    Ini mencegah tombol toggle melampaui lebar layar kontainer di HP Android 360px yang menyebabkan scroll kesamping yang tidak diinginkan.
  • 9 & 12 Segmen Grid: Diatur responsif agar beralih menjadi 1 kolom penuh di layar mobile: 
    className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6"

3. Grid Kartu Anggota (StrukturOrganisasi.tsx)

Layout card profile seksi diatur menggunakan kolom adaptif berikut:

className="grid grid-cols-1 xs:grid-cols-2 md:grid-cols-3 lg:grid-cols-5 gap-6"

Ini mencegah card anggota menyempit ekstrem di bawah 360px yang membuat teks peran/nama menumpuk tidak terbaca.

4. Kategori Tab & Detail Buku (KatalogBuku.tsx)

  • Horizontal Kategori Scroll: Baris pilihan kategori menggunakan horizontal scroll (overflow-x-auto) dengan tambahan efek gradasi bayangan transparan (gradient fade) di sisi kiri/kanan sebagai petunjuk visual bahwa daftar tersebut dapat digeser.
  • Panel Detail Buku: Samping panel detail buku (max-w-md) beralih menjadi lebar penuh (w-full) saat diakses dari HP agar sinopsis dan tombol peminjaman memiliki ruang klik yang nyaman.

5. Overflow Tabel Jadwal (JadwalLayanan.tsx)

Tabel jadwal layanan dibungkus menggunakan kontainer responsive scroll:

<div className="w-full overflow-x-auto rounded-lg border">
  <table ...>
</div>

Ini membiarkan tabel tetap berukuran aslinya tetapi dapat di-scroll ke kanan di mobile tanpa merusak lebar layout halaman utama.

Bab 3: Responsivitas Modul Booking Enkapsulasi

Penyelarasan modul formulir booking enkapsulasi agar mudah diisi oleh pengguna menggunakan jari di HP Android.

1. Menghilangkan CSS Inline Hack (BookingPage.tsx)

Masalah: CSS Selector Hack Statis
Halaman booking sebelumnya menggunakan modifikasi CSS override paksa: 
div[style*="grid-template-columns: minmax(0, 1fr) minmax(0, 300px)"] { ... }
Metode ini sangat rapuh. Sedikit perubahan markup akan membatalkan aturan ini.

Solusi:

Ganti baris grid statis menggunakan kelas responsif Tailwind CSS bawaan React:

className="grid grid-cols-1 lg:grid-cols-[1fr_300px] gap-8"

2. Ukuran Cell Kalender (BookingCalendar.tsx)

Pada layar Android di bawah 360px, cell kalender berukuran statis dengan padding tebal akan berdempetan dan teks angka tanggal akan bertumpuk.

Solusi:

  • Gunakan unit ukuran relatif (aspect-square) pada elemen cell hari.
  • Gunakan padding kecil di mobile pada container kalender (p-2 sm:p-4) agar kalender melebar maksimal mengikuti lebar HP.

3. Pill Date Header & Tombol Ganti (BookingForm.tsx)

Di mobile, baris header tanggal terpilih dan tombol "Ganti Tanggal" diatur bertumpuk vertikal (flex-col) agar tombol ganti tidak menabrak teks tanggal terpilih yang panjang.

Bab 4: Penyesuaian Responsivitas UI Panel Admin

Meskipun dashboard admin lebih sering diakses melalui desktop, penyesuaian mobile-friendly sangat penting agar admin dapat menyetujui booking secara cepat via notifikasi Telegram di HP.

1. Collapsible Sidebar (AdminLayout.tsx)

Sidebar admin diatur dengan laci (drawer) yang dapat dibuka/tutup menggunakan tombol hamburger:

<aside className="fixed inset-y-0 left-0 z-50 w-64 transform -translate-x-full md:translate-x-0 md:relative transition-transform duration-300 ease-in-out">
  • Tambahkan overlay bayangan hitam (backdrop) di belakang sidebar ketika aktif di mobile.
  • Sediakan tombol hamburger (hamburger menu icon) di header bagian atas yang hanya muncul di perangkat mobile (md:hidden).

2. Statistik & Chart Responsif (AdminDashboard.tsx)

  • Grid Statistik: Kartu jumlah anggota, buku, dan peminjaman diset responsif: 
    className="grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-4 gap-4"
  • Chart: Grafik aktivitas wajib dibungkus dengan komponen <ResponsiveContainer width="100%" height={300}> jika menggunakan Recharts agar grafik tidak keluar layar.

3. List-Card Pengganti Tabel di Mobile (AdminBookings.tsx)

Menampilkan data pemesanan di mobile menggunakan susunan kartu (card-based list) vertikal, bukan memaksakan tabel lebar:

Format Tampilan Mobile AdminBookings
Setiap data booking dibungkus dalam card yang memuat: Nama Pemesan, Tanggal Booking, Jumlah Dokumen, Status Badge, dan Tombol Aksi (Terima/Tolak/Reschedule) berukuran minimal 44px (touch target aman) agar mudah ditekan jari.

4. Pengelolaan Tabel Data & Formulir

  • Bungkus Overflow: Seluruh halaman pengelolaan (buku, anggota, dll.) wajib membungkus tabelnya di dalam kontainer scroll horizontal.
  • Formulir Input: Grid formulir diubah dari 2 kolom berdampingan menjadi 1 kolom penuh di mobile (grid-cols-1 md:grid-cols-2).
  • Fixed Bottom Bar: Berikan padding bawah (pb-24) pada formulir agar tombol simpan tidak tertutup oleh keyboard virtual Android.

Bab 5: Strategi Optimasi Gambar & Media

Optimasi gambar sangat krusial untuk menjaga agar First Contentful Paint (FCP) website di browser Android tetap di bawah 2 detik.

1. Apakah Komentar Kode Mempengaruhi Kecepatan Load?

Penjelasan: Proses Minification
TIDAK BERPENGARUH. Saat Anda menjalankan perintah npm run build, compiler Vite/Rollup akan melakukan proses Minification. Semua komentar, spasi berlebih, dan baris kosong akan dibuang dari file Javascript/CSS akhir. Menulis komentar dokumentasi sangat direkomendasikan dan tidak menambah ukuran loading.

2. Konversi Format & Kompresi

  • Gunakan WebP: Format WebP memiliki ukuran rata-rata 30% lebih kecil dibandingkan JPG atau PNG dengan kualitas visual yang sama.
  • Dimensi Tepat: Jangan mengunggah gambar resolusi asli 3000px jika hanya akan ditampilkan di kotak 300px. Selalu resize gambar sebelum diunggah.
  • Alat Bantu: Gunakan Squoosh.app atau TinyPNG untuk kompresi manual sebelum diunggah ke folder aset.

3. Optimasi Awan (Supabase Storage Transformation)

Jika aset disimpan di Supabase Storage, Anda dapat memanfaatkan rendering server untuk memperkecil gambar secara otomatis melalui parameter URL:

const getOptimizedUrl = (path, width = 300) => {
  const baseUrl = 'https://anqopdxzdkpsmtxuultp.supabase.co/storage/v1/render/image/public';
  return `${baseUrl}/${path}?width=${width}&quality=80&format=webp`;
}

4. Image Proxying & Lazy Loading

  • Image Proxy: Untuk gambar eksternal, gunakan CDN proxy seperti Cloudimage.io atau Cloudinary untuk memproses kompresi otomatis di server awan terdekat.
  • Atribut Lazy Loading: Tambahkan tag loading="lazy" pada semua gambar di bawah lipatan layar (below the fold) agar browser menunda unduhan sebelum di-scroll pengguna: 
    <img src={bookCover} alt="Cover Buku" loading="lazy" className="..." />
