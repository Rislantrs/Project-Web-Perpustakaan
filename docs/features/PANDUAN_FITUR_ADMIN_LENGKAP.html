Buku Panduan Komprehensif:
Struktur Berkas, Sakelar Fitur, & Kelola Admin

Panduan lengkap memahami letak berkas, penggantian aset gambar lokal, pengaktifan/penyembunyian fitur sirkulasi buku (katalog), otentikasi admin auto-confirm database, serta atribusi lisensi.

2. Rincian Fungsi Berkas src/

  • App.tsx: Mengatur sistem rute utama website, menentukan pembukaan halaman berdasarkan URL, dan memproteksi rute admin dari akses publik non-login.
  • Navbar.tsx & Footer.tsx: Komponen navigasi atas (responsive dropdown) dan bagian kaki halaman (memuat kontak dinas & jam operasional).
  • MemberCardQR.tsx: Menampilkan kartu anggota digital lengkap dengan sensor barcode / QR code dinamis.
  • siteConfig.ts: Pusat parameter dinamis instansi, pengaturan nama dinas, logo, warna primer, dan sakelar fitur global.
  • modules/booking/: Seluruh file modular yang melayani pengajuan enkapsulasi dokumen secara mandiri, baik menggunakan Supabase Repo maupun API Repo.
  • security/monitoring.ts: Memantau error javascript dan performa Core Web Vitals saat situs diakses oleh masyarakat.

Bab 2: Panduan Penggantian Aset Gambar Lokal

Panduan teknis mengganti file gambar yang terpasang langsung (hardcoded) di dalam tampilan halaman website.

1. Tiga Metode Penggantian Gambar

Metode A: Mengganti File Gambar Fisik (Paling Praktis)

Anda hanya perlu menimpa berkas gambar lama di direktori src/assets/ dengan file baru tanpa mengubah kode program. Syaratnya, nama file, ekstensi file (misal .webp), dan folder penyimpanan harus sama persis.

Contoh mengganti foto Gedung Arsip: Siapkan file baru, konversi ke format WebP, beri nama Gedung_Arsip.webp, lalu timpa file lama di folder src/assets/layanan/kearsipan/.

Metode B: Mengubah Import Path di Kode

Jika ingin menggunakan nama file baru atau memindahkannya ke folder lain, edit kode import komponen bersangkutan:

// Sebelum:
import gedungArsip from '../assets/layanan/kearsipan/Gedung_Arsip.webp';

// Sesudah:
import gedungArsip from '../assets/layanan/kearsipan/Gedung_Arsip_Baru.webp';

Metode C: Menggunakan URL Gambar Dinamis

Unggah file gambar ke **Supabase Storage bucket public** (misal: public-assets), salin URL publiknya, lalu ubah tag image di React:

<img src="https://[PROJECT_ID].supabase.co/storage/v1/object/public/assets/gedung-baru.webp" alt="Gedung" />

Bab 3: Sakelar Fitur (Feature Flags) & Konfigurasi Terpusat

Website ini dirancang fleksibel. Jika di masa depan instansi ingin menyembunyikan katalog buku dan pendaftaran anggota (merubah web menjadi profil dinas murni), Anda hanya perlu mengubah satu flag saja.

1. Mengubah Status Fitur di siteConfig.ts

Buka berkas **src/config/siteConfig.ts**, temukan objek **`FEATURES`** (sekitar baris 114):

FEATURES: {
  // true  = Mengaktifkan katalog buku & peminjaman
  // false = Menonaktifkan katalog & login secara total
  ENABLE_CATALOG: true, 
  
  REQUIRE_NIK: false,
  SHOW_DIGITAL_CARD: false,
}

2. Penyesuaian Otomatis Saat Parameter Diubah (false)

  • Sisi Pengunjung (Web Publik): Tautan menu "Katalog Buku", "Pabukon OPAC", serta tombol "Login / Register" otomatis disembunyikan dari navigasi header dan menu mobile.
  • Rute Terproteksi: Akses langsung via URL ke /katalog, /login, /profil, dsb. akan ditolak dan otomatis dialihkan ke halaman utama (Beranda).
  • Sisi Dashboard Admin: Menu kelola buku, kategori, peminjaman, dan kelola anggota disembunyikan dari sidebar navigasi. Statistik "Peminjaman Aktif" dan "Total Anggota" pada dashboard utama admin juga disembunyikan secara dinamis.

Bab 4: Panduan Langkah demi Langkah Menonaktifkan Fitur Sistem

Berikut adalah rincian kode yang diubah jika Anda menonaktifkan fitur secara manual di proyek:

Langkah 1: Mengubah Konfigurasi Global (siteConfig.ts)

FEATURES: {
- ENABLE_CATALOG: true,
+ ENABLE_CATALOG: false,

Langkah 2: Menyembunyikan Menu Admin (AdminLayout.tsx)

Menu Kelola Buku dan Kelola Member di sidebar admin dibungkus menggunakan kondisi javascript operator spread:

const navGroups = [
  ...
  {
    id: 'konten',
    title: 'Konten & Koleksi',
    items: [
-     { name: 'Kelola Buku', path: '/admin/books', icon: <BookOpen size={20} /> },
-     { name: 'Kelola Kategori', path: '/admin/categories', icon: <Tags size={20} /> },
+     ...(SITE_CONFIG.FEATURES.ENABLE_CATALOG ? [
+       { name: 'Kelola Buku', path: '/admin/books', icon: <BookOpen size={20} /> },
+       { name: 'Kelola Kategori', path: '/admin/categories', icon: <Tags size={20} /> },
+     ] : []),
      { name: 'Semua Artikel', path: '/admin/articles', icon: <FileText size={20} /> },
    ]
  }
];

Langkah 3: Mengamankan Akses URL Admin (App.tsx)

Gunakan komponen <Navigate> untuk memblokir pengetikan URL langsung ke halaman kelola buku oleh admin:

<Route path="books" element={
  SITE_CONFIG.FEATURES.ENABLE_CATALOG ? <ManageBooks /> : <Navigate to="/admin" replace />
} />

Bab 5: Pembuatan Akun Admin Baru & Verifikasi Supabase

Panduan mendaftarkan akun pengelola/petugas perpustakaan baru ke dalam sistem.

1. Pilihan Metode Verifikasi Pembuatan Admin

  • Opsi A: Auto-Confirm (Sangat Direkomendasikan)
    Menggunakan fungsi RPC database PostgreSQL. Email admin langsung berstatus aktif/terverifikasi saat disimpan. **Kelebihan**: Bisa menggunakan email bebas/dummy (contoh: adminbaru@test.com) tanpa perlu email asli.
  • Opsi B: Verifikasi Email Asli (Bawaan Client-side)
    Menggunakan pendaftaran standar. Pemilik akun admin baru wajib membuka inbox email aslinya dan mengklik link konfirmasi dari Supabase sebelum bisa login.

2. Script SQL Pembuatan Admin Auto-Confirm (RPC)

Buka **SQL Editor** pada dashboard Supabase Anda, buka query kosong baru, tempel kode SQL berikut, lalu klik **Run**:

-- RPC FUNCTION: PEMBUATAN AKUN ADMIN AUTO-CONFIRM
CREATE OR REPLACE FUNCTION public.create_new_admin_user(
  admin_email text,
  admin_password text,
  admin_name text,
  admin_role text,
  avatar_col text
)
RETURNS uuid
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, auth
AS $$
DECLARE
  new_user_id uuid;
  encrypted_pw text;
BEGIN
  -- 1. Validasi Akses: Hanya super_admin yang boleh memanggil fungsi ini
  IF NOT public.is_super_admin_from_admins() THEN
    RAISE EXCEPTION 'Akses ditolak: Hanya Super Admin yang dapat membuat admin baru.';
  END IF;

  -- 2. Cek Duplikasi
  IF EXISTS (SELECT 1 FROM public.admins WHERE lower(email) = lower(admin_email)) THEN
    RAISE EXCEPTION 'Email admin sudah terdaftar.';
  END IF;

  new_user_id := gen_random_uuid();
  encrypted_pw := crypt(admin_password, gen_salt('bf', 10)); -- Blowfish Hashing

  -- 3. Masukkan ke tabel Auth Users (langkah auto-confirm email)
  INSERT INTO auth.users (
    id, instance_id, aud, role, email, encrypted_password,
    email_confirmed_at, -- Mengisi waktu konfirmasi langsung saat ini
    raw_app_meta_data, raw_user_meta_data, created_at, updated_at, is_super_admin
  ) VALUES (
    new_user_id, '00000000-0000-0000-0000-000000000000', 'authenticated', 'authenticated',
    lower(admin_email), encrypted_pw, now(), -- Akun langsung terverifikasi!
    '{"provider":"email","providers":["email"]}', jsonb_build_object('namaLengkap', admin_name),
    now(), now(), false
  );

  -- 4. Masukkan ke profil admins
  INSERT INTO public.admins (
    id, nama_lengkap, email, password_hash, role, tanggal_dibuat, avatar_color
  ) VALUES (
    new_user_id, admin_name, lower(admin_email), encrypted_pw, admin_role,
    (EXTRACT(DAY FROM now())::text || ' ' ||
      CASE EXTRACT(MONTH FROM now())::int
        WHEN 1 THEN 'Januari' WHEN 2 THEN 'Februari' WHEN 3 THEN 'Maret'
        WHEN 4 THEN 'April' WHEN 5 THEN 'Mei' WHEN 6 THEN 'Juni'
        WHEN 7 THEN 'Juli' WHEN 8 THEN 'Agustus' WHEN 9 THEN 'September'
        WHEN 10 THEN 'Oktober' WHEN 11 THEN 'November' WHEN 12 THEN 'Desember'
      END || ' ' || EXTRACT(YEAR FROM now())::text),
    avatar_col
  );

  RETURN new_user_id;
END;
$$;

REVOKE ALL ON FUNCTION public.create_new_admin_user(text, text, text, text, text) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION public.create_new_admin_user(text, text, text, text, text) TO authenticated;
