Buku Panduan Komprehensif:
Server, Hosting, dan Deployment

Panduan teknis lengkap penyebaran (deployment) aplikasi React, konfigurasi domain, setup server VPS Linux mandiri, SSL, manajemen daemon PM2, SMTP transaksional, dan integrasi subdomain.

Bab 1: Penjelasan Sederhana Teknologi & Pilihan Hosting

Bab ini ditujukan bagi pembaca non-teknis atau pihak manajemen instansi untuk memahami arsitektur website Disipusda menggunakan analogi sederhana sehari-hari.

1. Analogi Restoran: Bagaimana Website Bekerja?

Bayangkan website perpustakaan digital Anda seperti sebuah Rumah Makan (Restoran) yang melayani pelanggan:

A. Frontend (React / TypeScript) ➡️ "Ruang Makan & Pelayan"

  • Ini adalah area visual yang disentuh oleh pelanggan (seperti meja, kursi, lampu hias, daftar menu, dan pelayan yang mencatat pesanan).
  • Di website, bagian inilah yang menampilkan gambar, tombol booking, form register, dan teks artikel secara rapi di layar HP pengunjung.

B. Backend API (Skrip Server) ➡️ "Juru Masak / Koki di Dapur"

  • Ini adalah dapur tempat koki mengolah bahan makanan. Pelanggan di ruang makan tidak dapat melihat dapur, tetapi mereka menerima makanan matang lewat pelayan.
  • Di server, dapur ini memproses keamanan password, memeriksa sisa kuota booking tanggal tertentu, dan mengirimkan email notifikasi.

C. Database (MySQL / PostgreSQL / Supabase) ➡️ "Gudang Bahan Makanan"

  • Ini adalah kulkas besar di belakang dapur tempat menyimpan seluruh persediaan bahan mentah secara teratur.
  • Di server, lemari arsip ini menyimpan data anggota, daftar buku, log denda, dan token keamanan.

2. Penting: Apakah Kode Program Harus Dirombak Total?

Jawabannya: SAMA SEKALI TIDAK.
Kode tampilan (React) tidak perlu dibuang atau ditulis ulang ke bahasa PHP jika Anda pindah hosting ke Hostinger. Ketika proses pengembangan selesai, program React dikompilasi menjadi file statis biasa (HTML, CSS, JS) di folder dist/. File ini bersifat mandiri dan dapat diunggah ke server web manapun di seluruh dunia, termasuk Hostinger.

3. Kamus Sederhana Istilah Teknologi (Glossary)

  • Vite / React: Mesin perancang tampilan agar web terasa responsif, cepat, dan "hidup".
  • Database (MySQL / PostgreSQL): Lemari arsip digital tempat menyimpan semua tulisan data website.
  • API (Application Programming Interface): Jembatan pos surat yang mengantarkan data dari layar browser ke database.
  • CORS: Satpam browser yang membatasi agar web server Anda tidak dapat diakses sembarangan oleh website asing.
  • SMTP: Sistem pengiriman email notifikasi otomatis agar tidak masuk ke folder SPAM.
  • Cron Job: Alarm otomatis yang berbunyi secara terjadwal untuk memicu fungsi harian (seperti cek denda telat buku).
  • PM2: Penjaga backend di server VPS agar server Node.js tidak mati saat terminal ditutup.

Bab 2: Panduan Migrasi Hosting Terpadu (Hostinger & VPS)

Strategi memigrasikan website Disipusda (React Frontend + Database & Server API) secara mandiri ke penyedia hosting terpadu seperti Hostinger atau VPS.

1. Alur Deployment Server Backend Node.js di Hostinger (hPanel)

  1. Masuk ke panel **Hostinger hPanel** > buka menu **Node.js Configuration**.
  2. Buat folder baru di luar folder publik utama Anda, misalnya: /home/user/apps/backend-api/.
  3. Unggah berkas backend Express Anda beserta package.json dan file .env ke folder tersebut.
  4. Setel konfigurasi Node.js di hPanel:
    • App Directory: /home/user/apps/backend-api/
    • Entry File: server.js
    • Node.js Version: Pilih versi terbaru (misal: 18 atau 20).
  5. Klik **Install NPM Modules** untuk menginstal semua dependency.
  6. Klik **Start** untuk menyalakan server API Anda.

2. Konfigurasi VPS Linux Mandiri (Ubuntu/Debian)

A. Menjalankan Aplikasi dengan PM2 (Daemon)

PM2 memastikan aplikasi backend Node.js Anda tetap berjalan di latar belakang secara terus-menerus:

# 1. Install Node.js dan PM2 di VPS
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt-get install -y nodejs
npm install pm2 -g

# 2. Masuk ke folder proyek dan jalankan aplikasi
cd /var/www/disipusda-api
npm install
pm2 start server.js --name "disipusda-backend-api"

# 3. Simpan konfigurasi agar auto-start saat reboot
pm2 startup systemd
pm2 save

B. Konfigurasi Nginx Reverse Proxy

Nginx bertugas menangkap lalu lintas port publik 80/443 dan mengarahkannya ke port internal Node.js (misal: 3000):

# Buat berkas konfigurasi virtual host Nginx baru
sudo nano /etc/nginx/sites-available/api.conf

Tempel konfigurasi server block berikut:

server {
    listen 80;
    server_name api.disipusda.purwakartakab.go.id;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
# Aktifkan konfigurasi dan restart Nginx
sudo ln -s /etc/nginx/sites-available/api.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

C. Memasang SSL Let's Encrypt Gratis

sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d api.disipusda.purwakartakab.go.id

3. Konfigurasi Pengiriman Email SMTP

Agar notifikasi email sirkulasi dapat dikirimkan secara mandiri tanpa Supabase/Resend API cloud:

Skrip Node.js (Nodemailer)

const nodemailer = require('nodemailer');

const transporter = nodemailer.createTransport({
  host: 'smtp.hostinger.com',
  port: 465,
  secure: true, // SSL
  auth: {
    user: 'no-reply@disipusda.purwakartakab.go.id',
    pass: 'Password_SMTP_Anda'
  }
});

4. Setup Cron Jobs (Tugas Harian Sirkulasi)

Gunakan crontab bawaan Linux VPS dengan perintah crontab -e untuk memicu pengecekan denda harian setiap jam 07:00 pagi secara lokal:

0 7 * * * /usr/bin/node /var/www/disipusda-api/cron/overdueCheck.js >> /var/log/cron-overdue.log 2>&1

Bab 3: Custom Domain, Vercel, dan Integrasi Supabase

Panduan hosting alternatif yang cepat menggunakan Vercel (Frontend React) dan Supabase Cloud (Backend Database).

1. Hosting Website React ke Vercel via GitHub

  1. Push kode proyek frontend Anda ke dalam repositori **GitHub**.
  2. Buka dashboard [Vercel](https://vercel.com) > hubungkan akun GitHub Anda.
  3. Klik **Add New** > **Project** > Import repositori website perpustakaan Anda.
  4. Pada bagian **Environment Variables**, masukkan VITE_SUPABASE_URL dan VITE_SUPABASE_ANON_KEY.
  5. Klik **Deploy**. Website Anda akan aktif di subdomain vercel gratis (contoh: disipusda.vercel.app).

2. Menghubungkan Domain Name.com ke Vercel

  1. Masuk ke proyek Anda di dashboard Vercel > **Settings** > **Domains** > tambahkan domain resmi Anda (contoh: perpustakaandaerah.com).
  2. Masuk ke akun [Name.com](https://www.name.com) > klik nama domain Anda > buka menu **DNS Management**.
  3. Tambahkan 2 records berikut di DNS Name.com:
    • A Record: Host/Name = @, Value = 76.76.21.21 (IP Vercel)
    • CNAME Record: Host/Name = www, Value = cname.vercel-dns.com
  4. Tunggu proses penyebaran DNS (propagasi) selama 15 menit hingga 1 jam hingga status di Vercel berubah menjadi hijau (Active).

3. Mendaftarkan Variabel Environment untuk Keamanan API Key

Daftarkan Anon Key dan URL Supabase Anda di Vercel Dashboard demi keamanan. Jangan pernah mengunggah file .env lokal Anda ke repositori GitHub karena file tersebut diabaikan secara default oleh .gitignore demi mencegah pencurian API Key.

Bab 4: Konfigurasi Navigasi Balik Subdomain ke Website Utama

Strategi mengarahkan tautan beranda subdomain booking kembali ke website portal utama instansi.

1. Langkah 1: Pengaturan URL Web Utama di .env

Buka file .env pada subdomain Anda, lalu daftarkan alamat URL portal web utama (misal: WordPress):

VITE_MAIN_WEBSITE_URL=https://web-utama-wordpress.com

2. Langkah 2: Cara Kerja Navbar Dinamis

Logika navbar telah dimodifikasi agar mendeteksi apabila tautan beranda mengarah ke luar subdomain:

const homeUrl = (import.meta.env.VITE_MAIN_WEBSITE_URL as string) || '/';
const isExternal = (path) => path.startsWith('http://') || path.startsWith('https://');

Jika terdeteksi eksternal, menu navigasi akan memicu pemanggilan tag jangkar HTML biasa (<a href="...">) untuk melompat keluar dari aplikasi React Router secara aman.
