Buku Panduan Komprehensif:
Server, Hosting, dan Deployment

Panduan teknis lengkap penyebaran (deployment) aplikasi React, konfigurasi domain, setup server VPS Linux mandiri, SSL, manajemen daemon PM2, SMTP transaksional, dan integrasi subdomain.

Diperbarui: Juni 2026 | Disusun oleh: M. Rislan Tristansyah (Mahasiswa Sistem Telekomunikasi)

Bab 1: Penjelasan Sederhana Teknologi & Pilihan Hosting

Bab ini ditujukan bagi pembaca non-teknis atau pihak manajemen instansi untuk memahami arsitektur website Disipusda menggunakan analogi sederhana sehari-hari.

1. Analogi Restoran: Bagaimana Website Bekerja?

Bayangkan website perpustakaan digital Anda seperti sebuah Rumah Makan (Restoran) yang melayani pelanggan:

A. Frontend (React / TypeScript) ➡️ "Ruang Makan & Pelayan"

  • Ini adalah area visual yang disentuh oleh pelanggan (seperti meja, kursi, lampu hias, daftar menu, dan pelayan yang mencatat pesanan).
  • Di website, bagian inilah yang menampilkan gambar, tombol booking, form register, dan teks artikel secara rapi di layar HP pengunjung.

B. Backend API (Skrip Server) ➡️ "Juru Masak / Koki di Dapur"

  • Ini adalah dapur tempat koki mengolah bahan makanan. Pelanggan di ruang makan tidak dapat melihat dapur, tetapi mereka menerima makanan matang lewat pelayan.
  • Di server, dapur ini memproses keamanan password, memeriksa sisa kuota booking tanggal tertentu, dan mengirimkan email notifikasi.

C. Database (MySQL / PostgreSQL / Supabase) ➡️ "Gudang Bahan Makanan"

  • Ini adalah kulkas besar di belakang dapur tempat menyimpan seluruh persediaan bahan mentah secara teratur.
  • Di server, lemari arsip ini menyimpan data anggota, daftar buku, log denda, dan token keamanan.

2. Penting: Apakah Kode Program Harus Dirombak Total?

Jawabannya: SAMA SEKALI TIDAK.
Kode tampilan (React) tidak perlu dibuang atau ditulis ulang ke bahasa PHP jika Anda pindah hosting ke Hostinger. Ketika proses pengembangan selesai, program React dikompilasi menjadi file statis biasa (HTML, CSS, JS) di folder dist/. File ini bersifat mandiri dan dapat diunggah ke server web manapun di seluruh dunia, termasuk Hostinger.

3. Kamus Sederhana Istilah Teknologi (Glossary)

  • Vite / React: Mesin perancang tampilan agar web terasa responsif, cepat, dan "hidup".
  • Database (MySQL / PostgreSQL): Lemari arsip digital tempat menyimpan semua tulisan data website.
  • API (Application Programming Interface): Jembatan pos surat yang mengantarkan data dari layar browser ke database.
  • CORS: Satpam browser yang membatasi agar web server Anda tidak dapat diakses sembarangan oleh website asing.
  • SMTP: Sistem pengiriman email notifikasi otomatis agar tidak masuk ke folder SPAM.
  • Cron Job: Alarm otomatis yang berbunyi secara terjadwal untuk memicu fungsi harian (seperti cek denda telat buku).
  • PM2: Penjaga backend di server VPS agar server Node.js tidak mati saat terminal ditutup.

Bab 2: Panduan Migrasi Hosting Terpadu (Hostinger & VPS)

Strategi memigrasikan website Disipusda (React Frontend + Database & Server API) secara mandiri ke penyedia hosting terpadu seperti Hostinger atau VPS.

1. Alur Deployment Server Backend Node.js di Hostinger (hPanel)

  1. Masuk ke panel **Hostinger hPanel** > buka menu **Node.js Configuration**.
  2. Buat folder baru di luar folder publik utama Anda, misalnya: /home/user/apps/backend-api/.
  3. Unggah berkas backend Express Anda beserta package.json dan file .env ke folder tersebut.
  4. Setel konfigurasi Node.js di hPanel:
    • App Directory: /home/user/apps/backend-api/
    • Entry File: server.js
    • Node.js Version: Pilih versi terbaru (misal: 18 atau 20).
  5. Klik **Install NPM Modules** untuk menginstal semua dependency.
  6. Klik **Start** untuk menyalakan server API Anda.

2. Konfigurasi VPS Linux Mandiri (Ubuntu/Debian)

A. Menjalankan Aplikasi dengan PM2 (Daemon)

PM2 memastikan aplikasi backend Node.js Anda tetap berjalan di latar belakang secara terus-menerus:

# 1. Install Node.js dan PM2 di VPS
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt-get install -y nodejs
npm install pm2 -g

# 2. Masuk ke folder proyek dan jalankan aplikasi
cd /var/www/disipusda-api
npm install
pm2 start server.js --name "disipusda-backend-api"

# 3. Simpan konfigurasi agar auto-start saat reboot
pm2 startup systemd
pm2 save

B. Konfigurasi Nginx Reverse Proxy

Nginx bertugas menangkap lalu lintas port publik 80/443 dan mengarahkannya ke port internal Node.js (misal: 3000):

# Buat berkas konfigurasi virtual host Nginx baru
sudo nano /etc/nginx/sites-available/api.conf

Tempel konfigurasi server block berikut:

server {
    listen 80;
    server_name api.disipusda.purwakartakab.go.id;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
# Aktifkan konfigurasi dan restart Nginx
sudo ln -s /etc/nginx/sites-available/api.conf /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

C. Memasang SSL Let's Encrypt Gratis

sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d api.disipusda.purwakartakab.go.id

3. Konfigurasi Pengiriman Email SMTP

Agar notifikasi email sirkulasi dapat dikirimkan secara mandiri tanpa Supabase/Resend API cloud:

Skrip Node.js (Nodemailer)

const nodemailer = require('nodemailer');

const transporter = nodemailer.createTransport({
  host: 'smtp.hostinger.com',
  port: 465,
  secure: true, // SSL
  auth: {
    user: 'no-reply@disipusda.purwakartakab.go.id',
    pass: 'Password_SMTP_Anda'
  }
});

4. Setup Cron Jobs (Tugas Harian Sirkulasi)

Gunakan crontab bawaan Linux VPS dengan perintah crontab -e untuk memicu pengecekan denda harian setiap jam 07:00 pagi secara lokal:

0 7 * * * /usr/bin/node /var/www/disipusda-api/cron/overdueCheck.js >> /var/log/cron-overdue.log 2>&1

Bab 3: Deployment Cloudflare Pages, DNS Name.com ke Cloudflare, dan Integrasi Resend

Panduan lengkap cara mendeploy frontend React ke platform global Cloudflare Pages, memindahkan manajemen DNS dari registrar luar (seperti Name.com) ke Cloudflare, dan mengonfigurasi email transaksional Resend.

1. Mengapa Menggunakan Cloudflare Pages?

Kelebihan Cloudflare Pages
Cloudflare Pages menawarkan hosting statis gratis dengan CDN tercepat di dunia, SSL otomatis, build tak terbatas dari GitHub, perlindungan DDoS bawaan, dan fitur Variables and Secrets untuk mengamankan API Key Anda (seperti Supabase URL dan Turnstile Site Key).

2. Langkah-Langkah Deploy React ke Cloudflare Pages (via GitHub)

  1. Push kode proyek website Anda ke repositori **GitHub** (bisa privat atau publik).
  2. Buka dashboard [Cloudflare](https://dash.cloudflare.com) > buka menu **Workers & Pages** > klik **Create Application** > pilih tab **Pages**.
  3. Klik **Connect to Git** > hubungkan akun GitHub Anda dan pilih repositori website perpustakaan Anda.
  4. Pada halaman **Build settings**:
    • Framework preset: Pilih Vite atau React.
    • Build command: npm run build
    • Build output directory: dist
  5. Klik **Save and Deploy**. Cloudflare akan membangun website Anda dan memberikan domain gratis bawaan (contoh: project-web-perpustakaan.pages.dev).

3. Memindahkan DNS Domain Luar (Name.com) ke Cloudflare

Agar domain yang dibeli dari Name.com dapat terintegrasi sempurna dengan Cloudflare Pages dan Resend, Anda harus memindahkan Nameserver Name.com ke Cloudflare:

  1. Pada dashboard Cloudflare, klik **Add a Site** > masukkan domain Anda (contoh: lann.codes).
  2. Pilih paket **Free** (Gratis).
  3. Cloudflare akan memindai records DNS lama Anda dan memberikan dua buah **Cloudflare Nameservers**:
    • daniella.ns.cloudflare.com
    • dimitris.ns.cloudflare.com
  4. Buka akun [Name.com](https://www.name.com) > klik domain Anda > cari menu **Nameservers** (atau *Change Nameservers*).
  5. Hapus nameserver bawaan Name.com, lalu masukkan kedua **Cloudflare Nameservers** di atas. Klik **Save**.
  6. Tunggu proses pemindahan nameserver (propagasi DNS) sekitar 10 menit hingga 1 jam hingga status domain Anda di Cloudflare menjadi **Active**.

4. Menghubungkan Custom Domain di Cloudflare Pages & DNS Records

  1. Buka proyek Pages Anda di Cloudflare > pilih tab **Custom Domains** > klik **Set up a custom domain**.
  2. Masukkan domain Anda (contoh: lann.codes) > ikuti petunjuknya. Cloudflare secara otomatis akan menambahkan record **CNAME** di tab DNS Anda dan membuat sertifikat SSL gratis (HTTPS).
  3. Di menu **DNS > Records** Cloudflare, pastikan Anda memiliki record domain utama:
    • Type: CNAME | Name: lann.codes | Target: project-web-perpustakaan.pages.dev | Proxy status: Proxied (Awan Oranye)
  4. ⚠️ **Mengatasi Peringatan www (Rekomendasi Utama):** Jika ada rekomendasi/peringatan dari Cloudflare bahwa pengunjung tidak dapat mengakses domain menggunakan www (seperti "Visitors cannot reach www.lann.codes"), tambahkan record baru berikut di DNS Cloudflare:
    • Type: CNAME | Name: www | Target: lann.codes atau project-web-perpustakaan.pages.dev | Proxy status: Proxied (Awan Oranye)

5. Konfigurasi DNS Resend.com di Dashboard Cloudflare

Buka dashboard **Resend.com > Domains** > salin records verifikasi Anda. Lalu buka dashboard **Cloudflare > DNS > Records** dan masukkan records berikut satu per satu:

PERINGATAN PROXY: GUNAKAN "DNS ONLY" (AWAN ABU-ABU)
Semua records verifikasi Resend (MX dan TXT) WAJIB diatur dengan Proxy Status = DNS Only (Grey Cloud). Jika Anda menyalakan Proxy (Awan Oranye), server Resend tidak akan mendeteksi records DNS tersebut dan status verifikasi akan tertunda selamanya.
Tipe Nama / Host Target / Value / Content Proxy Status TTL Prioritas / Keterangan
CNAME lann.codes project-web-perpustakaan.pages.dev Proxied (Oranye) Auto Untuk mengarahkan domain utama ke aplikasi React.
MX send feedback-smtp.us-east-1.amazonses.com DNS Only (Abu-abu) Auto Prioritas: 10 (Penanganan email memantul).
TXT _dmarc "v=DMARC1; p=none;" DNS Only (Abu-abu) Auto Kebijakan keamanan dasar email.
TXT resend._domainkey "p=MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQ..." DNS Only (Abu-abu) Auto DKIM: Kunci tanda tangan email dari Resend.
TXT send "v=spf1 include:amazonses.com ~all" DNS Only (Abu-abu) Auto SPF: Server resmi pengirim email.

6. Pengaturan Environment Variables dan Secrets di Cloudflare Pages

Website React Anda membutuhkan API Keys untuk mengakses Supabase dan Cloudflare Turnstile (Captcha). Jangan hardcode nilai ini di dalam kode program, melainkan daftarkan di dashboard Cloudflare Pages:

  1. Di dashboard Cloudflare, buka menu **Workers & Pages** > klik proyek aplikasi Anda (contoh: project-web-perpustakaan).
  2. Masuk ke menu **Settings** (di tab atas) > pilih **Configuration** > cari bagian **Variables and Secrets**.
  3. Pada bagian **Environment variables**, klik **Add** (atau **Edit**) untuk menambahkan variabel berikut:
Tipe Variabel Nama Variabel (Variable Name) Nilai Variabel (Value) Keterangan
Plaintext / Secret VITE_SUPABASE_URL https://anqopdxzdkpsmtxuultp.supabase.co URL endpoint API proyek Supabase Anda.
Plaintext / Secret VITE_SUPABASE_ANON_KEY eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... Kunci publik anonim Supabase (Anon Key).
Plaintext / Secret VITE_TURNSTILE_SITE_KEY 0x4AAAAAAADDtG5PHsGg6YoP2 Site Key publik Cloudflare Turnstile untuk verifikasi anti-bot login.
PENTING: LAKUKAN DEPLOY ULANG SETELAH UBAH VARIABEL
Setelah menambahkan atau mengubah nilai variabel di dashboard Cloudflare Pages, perubahan tersebut tidak akan langsung aktif di web live. Anda wajib memicu build ulang (misalnya melakukan push commit kecil baru ke GitHub atau memicu redeploy dari dashboard) agar Cloudflare mengompilasi ulang website dengan nilai variabel yang baru.

Bab 4: Konfigurasi Navigasi Balik Subdomain ke Website Utama

Strategi mengarahkan tautan beranda subdomain booking kembali ke website portal utama instansi.

1. Langkah 1: Pengaturan URL Web Utama di .env

Buka file .env pada subdomain Anda, lalu daftarkan alamat URL portal web utama (misal: WordPress):

VITE_MAIN_WEBSITE_URL=https://web-utama-wordpress.com

2. Langkah 2: Cara Kerja Navbar Dinamis

Logika navbar telah dimodifikasi agar mendeteksi apabila tautan beranda mengarah ke luar subdomain:

const homeUrl = (import.meta.env.VITE_MAIN_WEBSITE_URL as string) || '/';
const isExternal = (path) => path.startsWith('http://') || path.startsWith('https://');

Jika terdeteksi eksternal, menu navigasi akan memicu pemanggilan tag jangkar HTML biasa (<a href="...">) untuk melompat keluar dari aplikasi React Router secara aman.
