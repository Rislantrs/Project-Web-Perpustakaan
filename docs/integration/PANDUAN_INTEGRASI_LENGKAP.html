Integrasi API & Layanan Eksternal

Panduan teknis menyeluruh untuk menghubungkan sistem otentikasi Google OAuth, SMTP Resend.com, Supabase Edge Functions, database pendaftaran, Telegram Bot, WhatsApp Gateway, dan sinkronisasi REST API WordPress.

Bab 1: Integrasi Google OAuth (Google Sign-In)

Fitur ini memungkinkan pemohon dan anggota perpustakaan untuk mendaftar dan masuk secara instan ke sistem web perpustakaan menggunakan akun Google mereka.

1. Membuat Kredensial di Google Cloud Console

  1. Buka halaman Google Cloud Console.
  2. Buat proyek baru dengan nama Disipusda Perpustakaan, lalu masuk ke proyek tersebut.
  3. Buka menu OAuth consent screen di sidebar kiri:
    • Pilih External sebagai User Type agar dapat diakses oleh semua akun Gmail.
    • Masukkan informasi nama aplikasi (Disipusda Purwakarta) dan isi email dukungan Anda.
    • Klik Save and Continue hingga selesai, kemudian klik Publish App di halaman ringkasan agar statusnya menjadi aktif (Live).
  4. Buka menu Credentials di sidebar kiri:
    • Klik tombol + Create Credentials > pilih OAuth client ID.
    • Pilih jenis aplikasi Web application.
    • Authorized JavaScript origins: Tambahkan domain asal Anda, misalnya:
      • http://localhost:5173 (untuk pengembangan lokal)
      • https://lann.codes (domain staging)
      • https://disipusda.purwakartakab.go.id (domain produksi)
    • Authorized redirect URIs: Tambahkan URL Callback redirect dari Supabase Anda secara persis: 
      https://anqopdxzdkpsmtxuultp.supabase.co/auth/v1/callback
  5. Klik Create. Salin Client ID dan Client Secret yang muncul pada kotak dialog.

2. Memasang OAuth Keys di Dashboard Supabase

  1. Masuk ke dashboard Supabase > Auth > Providers > Google.
  2. Aktifkan sakelar Enable Google Provider.
  3. Tempelkan Client ID dan Client Secret yang telah disalin sebelumnya pada kolom input yang tersedia.
  4. Klik Save.

Bab 2: Integrasi Resend SMTP & Edge Functions ke Supabase

Supabase secara bawaan membatasi kuota pengiriman email otomatis. Untuk kebutuhan produksi, email dialihkan ke server **SMTP Resend.com** dan logika kustom di-deploy ke **Supabase Edge Functions**.

1. Konfigurasi SMTP Resend pada Supabase Auth

  1. Masuk ke Resend.com > API Keys, lalu buat kunci API baru dengan izin pengiriman email (Sending access).
  2. Masuk ke dashboard Supabase > Auth > SMTP Settings.
  3. Aktifkan sakelar Enable Custom SMTP.
  4. Isi parameter SMTP di bawah ini secara tepat:
    • Sender Email: Email domain resmi Anda yang sudah terverifikasi di Resend (contoh: no-reply@lann.codes).
    • Sender Name: Disipusda Purwakarta
    • SMTP Host: smtp.resend.com
    • Port: 465 (direkomendasikan) atau 587
    • SMTP Username: resend (wajib huruf kecil)
    • SMTP Password: Masukkan kunci API Key Resend Anda (berawalan re_...).
  5. Klik Save Changes.

2. Mendaftarkan Custom Secrets (Environment Variables) di Supabase

Edge Functions membutuhkan variabel lingkungan yang berisi kunci rahasia untuk memanggil API Resend and Telegram. Tambahkan rahasia ini di dashboard Supabase melalui menu Settings > Edge Functions > Custom Secrets:

Nama Secret Nilai / Value Keterangan Fungsi
RESEND_API_KEY re_xxxxxxxxxxx API Key akun Resend untuk pengiriman email transaksional kustom.
RESEND_FROM_EMAIL Disipusda <no-reply@lann.codes> Alamat pengirim email sistem yang sudah disetujui di Resend.
TELEGRAM_BOT_TOKEN 123456:ABC-DEFxxxx Token bot Telegram dari @BotFather untuk notifikasi admin.
TELEGRAM_ADMIN_CHAT_ID -100xxxxxx atau 9876543 ID chat atau ID grup Telegram admin penerima laporan.
SITE_URL https://lann.codes URL utama frontend untuk menyusun tautan reschedule di dalam email.
CRON_SECRET String_Acak_Rahasia_Panjang Token validasi untuk mengamankan eksekusi penjadwalan otomatis.

Atau setel secara massal menggunakan perintah terminal Supabase CLI:

supabase secrets set RESEND_API_KEY="re_..." RESEND_FROM_EMAIL="..." TELEGRAM_BOT_TOKEN="..." TELEGRAM_ADMIN_CHAT_ID="..." SITE_URL="..." CRON_SECRET="..."

3. Mendeploy 6 Custom Edge Functions ke Supabase

Unggah program backend serverless dari direktori lokal supabase/functions/ ke server awan Supabase:

  1. Hubungkan terminal lokal ke proyek Supabase: 
    supabase login
supabase link --project-ref anqopdxzdkpsmtxuultp
  2. Jalankan perintah deploy untuk keenam fungsi: 
    supabase functions deploy booking-notification
supabase functions deploy booking-status-change
supabase functions deploy send-booking-digest
supabase functions deploy send-borrow-notification
supabase functions deploy send-borrow-reminders
supabase functions deploy telegram-webhook

Bab 3: Setup Supabase Native Cron Jobs (pg_cron & pg_net)

Website memerlukan mekanisme pemanggilan tugas otomatis harian (Cron Job) tanpa mengandalkan pemicu eksternal.

1. Mengaktifkan Ekstensi Database

Masuk ke dashboard Supabase > Database > Extensions, lalu aktifkan dua modul berikut:

  • pg_cron: Mengelola penjadwalan query berbasis ekspresi cron.
  • pg_net: Mengizinkan database melakukan pemanggilan request HTTP (POST/GET) secara asinkron.

2. Menjadwalkan Pengingat Peminjaman Harian via SQL Editor

Buka menu SQL Editor di Supabase, buat query baru, lalu jalankan script berikut:

-- Hapus job lama jika terdaftar agar tidak duplikasi
SELECT cron.unschedule('kirim-pengingat-peminjaman-harian');

-- Jadwalkan cron job baru (Berjalan otomatis setiap hari pukul 08:00 UTC)
SELECT cron.schedule(
  'kirim-pengingat-peminjaman-harian',
  '0 8 * * *',
  $$
  SELECT net.http_post(
    url := 'https://anqopdxzdkpsmtxuultp.supabase.co/functions/v1/send-borrow-reminders',
    headers := '{"Content-Type": "application/json", "x-cron-secret": "MASUKKAN_CRON_SECRET_SAMA_DENGAN_SECRETS"}'::jsonb,
    body := '{}'::jsonb
  );
  $$
);

Bab 4: Panduan Setup Domain Resend di DNS Cloudflare & Registrar

Verifikasi kepemilikan domain di Resend.com wajib dilakukan agar email dikirim atas nama domain Anda sendiri dan tidak diblokir oleh filter spam.

1. Menambahkan Domain di Dashboard Resend

  1. Buka dashboard Resend > Domains > Add Domain.
  2. Masukkan domain utama Anda (contoh: lann.codes).
  3. Pilih Region terdekat (contoh: us-east-1), lalu klik Add.

2. Tabel DNS Records Verifikasi

Tambahkan 4 baris records berikut pada manajer DNS domain Anda (Name.com atau Cloudflare):

PERINGATAN PROXY CLOUDFLARE
Seluruh records verifikasi Resend (DKIM, SPF, MX) wajib diset ke status DNS Only (Awan Abu-abu). Jangan gunakan status Proxied (Awan Oranye) agar server Resend dapat memvalidasi records tersebut.
Tipe Host / Name Isi / Value / Target Prioritas Status Proxy
TXT resend._domainkey p=MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQ... - DNS Only (Abu-abu)
TXT send v=spf1 include:amazonses.com ~all - DNS Only (Abu-abu)
MX send feedback-smtp.us-east-1.amazonses.com 10 DNS Only (Abu-abu)
TXT _dmarc v=DMARC1; p=none; - DNS Only (Abu-abu)

3. Cara Cek Hasil Autentikasi di Gmail

Kirim email uji coba dari sistem Anda ke akun Gmail, buka email tersebut, klik tombol titik tiga di pojok kanan atas > pilih **Tampilkan Asli (Show Original)**. Pastikan tabel teratas menunjukkan:

  • SPF: PASS (dengan domain send.lann.codes)
  • DKIM: PASS (dengan domain lann.codes)
  • DMARC: PASS

Bab 5: Integrasi & Deploy Modul Booking Enkapsulasi

Panduan deployment modul pemesanan (booking) enkapsulasi arsip dan penanganan multi-domain.

1. Skenario A: Modul Terpadu di Web Baru (Monolith)

Ini adalah konfigurasi standar di mana modul booking berjalan langsung di dalam proyek React + Vite yang baru.

  • Pastikan variabel environment berikut terdaftar di hosting Anda: 
    VITE_ENABLE_BOOKING=true
VITE_BOOKING_DB_MODE=supabase
  • Modul akan aktif di menu navigasi utama dan rute halaman /booking-enkapsulasi dapat diakses.

2. Skenario B: Memindahkan Modul ke Web Lama (React/PHP)

  • Untuk React / Next.js: Salin seluruh folder src/modules/booking/ ke proyek web lama. Pasang dependensi yang dibutuhkan: 
    npm install xlsx jspdf jspdf-autotable motion lucide-react sonner
  • Untuk PHP (Laravel / cPanel / HTML Statis): Gunakan teknik Micro Frontend dengan menempelkan tag <iframe> ke halaman web lama Anda: 
    <iframe src="https://booking.domainbaru.com/booking-enkapsulasi" width="100%" height="900px" frameborder="0"></iframe>

3. Skenario C: Menjalankan di Subdomain Terpisah (Berbagi Database)

Anda dapat menjalankan halaman booking di domain tersendiri (misal: booking.disipusda.com) namun tetap merekam data ke database yang sama dengan web utama:

  1. Arahkan subdomain baru ke build statis modul booking Anda.
  2. Pada file .env subdomain, arahkan parameter Supabase ke proyek Supabase milik website utama: 
    VITE_SUPABASE_URL=https://project-web-utama.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5c... (Anon Key Web Utama)

Bab 6: Integrasi Modul Booking React dengan WordPress REST API

Jika instansi meminta data pemesanan disimpan langsung ke dalam database WordPress (MySQL) milik website utama, Anda dapat memfungsikan modul booking dalam mode REST API.

1. Konfigurasi .env React (REST API Mode)

Ubah pengaturan database driver di file .env modul booking dari Supabase menjadi API:

VITE_BOOKING_DB_MODE=api
VITE_BOOKING_API_URL=https://web-utama-wordpress.com/wp-json/booking/v1
VITE_BOOKING_API_TOKEN=rahasia_token_keamanan_wp_disipusda

2. Membuat Tabel Database Kustom di WordPress (MySQL)

Buka phpMyAdmin di server cPanel WordPress Anda, pilih database WordPress, lalu jalankan query SQL berikut:

CREATE TABLE IF NOT EXISTS `wp_booking_enkapsulasi` (
  `id` VARCHAR(50) NOT NULL,
  `nama_lengkap` VARCHAR(150) NOT NULL,
  `email` VARCHAR(100) NOT NULL,
  `whatsapp` VARCHAR(20) NOT NULL,
  `instansi` VARCHAR(150) NOT NULL,
  `tanggal_booking` DATE NOT NULL,
  `jumlah_dokumen` INT NOT NULL DEFAULT 1,
  `status` VARCHAR(20) NOT NULL DEFAULT 'pending',
  `note` TEXT NULL,
  `reschedule_date` DATE NULL,
  `reschedule_note` TEXT NULL,
  `token_reschedule` VARCHAR(100) NULL,
  `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

3. Menambahkan Custom Endpoint di WordPress Theme (`functions.php`)

Buka berkas wp-content/themes/[tema-aktif]/functions.php dan tempelkan kode PHP berikut di baris paling akhir untuk menangani request API dari React:

// Registrasi Rute Endpoint Baru
add_action('rest_api_init', function () {
    register_rest_route('booking/v1', '/check-date', array(
        'methods'             => 'GET',
        'callback'            => 'wp_booking_check_date',
        'permission_callback' => 'wp_booking_check_auth',
    ));
    register_rest_route('booking/v1', '/bookings', array(
        'methods'             => 'POST',
        'callback'            => 'wp_booking_create_booking',
        'permission_callback' => 'wp_booking_check_auth',
    ));
    register_rest_route('booking/v1', '/calendar', array(
        'methods'             => 'GET',
        'callback'            => 'wp_booking_get_calendar',
        'permission_callback' => 'wp_booking_check_auth',
    ));
});

// Fungsi Autentikasi Bearer Token
function wp_booking_check_auth(WP_REST_Request $request) {
    $secure_token = 'rahasia_token_keamanan_wp_disipusda';
    $auth_header = $request->get_header('Authorization');
    if (!$auth_header) {
        return new WP_Error('no_auth', 'Token diperlukan.', array('status' => 401));
    }
    if (preg_match('/Bearer\s(\S+)/', $auth_header, $matches)) {
        if ($matches[1] === $secure_token) {
            return true;
        }
    }
    return new WP_Error('invalid_token', 'Token tidak valid.', array('status' => 403));
}

// Callback Cek Kuota Tanggal (GET /check-date?date=YYYY-MM-DD)
function wp_booking_check_date(WP_REST_Request $request) {
    global $wpdb;
    $date = sanitize_text_field($request->get_param('date'));
    if (empty($date)) {
        return new WP_REST_Response(array('available' => false), 400);
    }
    $max_quota = 5;
    $table_name = $wpdb->prefix . 'booking_enkapsulasi';
    $count = $wpdb->get_var($wpdb->prepare(
        "SELECT COUNT(*) FROM $table_name WHERE tanggal_booking = %s AND status != 'rejected' AND status != 'cancelled'",
        $date
    ));
    return new WP_REST_Response(array('available' => ($count < $max_quota)), 200);
}

// Callback Simpan Booking Baru (POST /bookings)
function wp_booking_create_booking(WP_REST_Request $request) {
    global $wpdb;
    $params = $request->get_json_params();
    if (empty($params['nama_lengkap']) || empty($params['tanggal_booking'])) {
        return new WP_REST_Response(array('success' => false), 400);
    }
    $table_name = $wpdb->prefix . 'booking_enkapsulasi';
    $booking_id = wp_generate_uuid4();
    $data = array(
        'id'              => $booking_id,
        'nama_lengkap'    => sanitize_text_field($params['nama_lengkap']),
        'email'           => sanitize_email($params['email']),
        'whatsapp'        => sanitize_text_field($params['whatsapp']),
        'instansi'        => sanitize_text_field($params['instansi']),
        'tanggal_booking' => sanitize_text_field($params['tanggal_booking']),
        'jumlah_dokumen'  => intval($params['jumlah_dokumen']),
        'status'          => 'pending',
    );
    $wpdb->insert($table_name, $data);
    return new WP_REST_Response(array('success' => true, 'id' => $booking_id), 201);
}

// Callback Data Kalender Keseluruhan (GET /calendar)
function wp_booking_get_calendar(WP_REST_Request $request) {
    global $wpdb;
    $year  = intval($request->get_param('year'));
    $month = intval($request->get_param('month'));
    $table_name = $wpdb->prefix . 'booking_enkapsulasi';
    $results = $wpdb->get_results($wpdb->prepare(
        "SELECT tanggal_booking, COUNT(*) as total_count FROM $table_name 
         WHERE YEAR(tanggal_booking) = %d AND MONTH(tanggal_booking) = %d AND status != 'rejected' AND status != 'cancelled'
         GROUP BY tanggal_booking",
        $year, $month
    ), ARRAY_A);
    $calendar_data = array();
    foreach ($results as $row) {
        $calendar_data[] = array(
            'date'  => $row['tanggal_booking'],
            'count' => intval($row['total_count']),
            'isFull' => (intval($row['total_count']) >= 5)
        );
    }
    return new WP_REST_Response(array('data' => $calendar_data), 200);
}

Bab 7: Perencanaan Notifikasi WhatsApp Gateway

Notifikasi via WhatsApp (WA) berjalan secara paralel di server-side untuk memastikan pemohon langsung mendapatkan pesan konfirmasi ke nomor HP mereka.

1. Analisis Alur Kerja Perubahan

  • Tidak Ada Perubahan Kode Frontend: Frontend hanya bertugas menembak Supabase Edge Functions. Seluruh proses integrasi WA diselesaikan di backend server-side.
  • Secrets Baru di Supabase: Anda wajib mendaftarkan rahasia token API WhatsApp Gateway Anda dengan nama: 
    WA_GATEWAY_TOKEN="token_dari_penyedia_gateway_anda"

2. Lokasi Komentar Placeholder di Berkas Kode Lokal

Komentar petunjuk pemicu pengiriman notifikasi WhatsApp telah ditambahkan di dalam Edge Functions berikut:

  1. supabase/functions/booking-notification/index.ts: Terletak di dalam blok paralel Promise.allSettled.
  2. supabase/functions/booking-status-change/index.ts: Terletak di bawah blok penyelesaian pengiriman email status perubahan.

3. Contoh Kode Implementasi Integrasi Deno & Fonnte.com

Berikut adalah cuplikan kode pembantu (helper function) Deno untuk melakukan post data ke Fonnte WhatsApp Gateway:

async function sendWhatsApp(target: string, message: string, token: string): Promise<void> {
  let cleanNumber = target.replace(/[^0-9]/g, '');
  if (cleanNumber.startsWith('0')) {
    cleanNumber = '62' + cleanNumber.slice(1);
  }

  const response = await fetch('https://api.fonnte.com/send', {
    method: 'POST',
    headers: {
      'Authorization': token,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      target: cleanNumber,
      message: message,
      countryCode: '62',
    }),
  });

  if (!response.ok) {
    const errorBody = await response.text();
    throw new Error(`Fonnte API Error: ${response.status} - ${errorBody}`);
  }
}

Bab 8: Mode Company Profile & Troubleshooting

Bagian akhir untuk memandu sakelar fitur Company Profile dan pemecahan masalah integrasi.

1. Mengubah Website Menjadi Company Profile Murni

Apabila instansi meminta fitur perpustakaan dinonaktifkan sementara dan website hanya menampilkan company profile portal informasi:

  1. Buka berkas konfigurasi lokal src/config/siteConfig.ts.
  2. Ubah properti ENABLE_CATALOG menjadi false: 
    FEATURES: {
  ENABLE_CATALOG: false, // Setel ke false
  REQUIRE_NIK: false,
  SHOW_DIGITAL_CARD: false,
}
  3. Sistem secara otomatis akan menyembunyikan tombol catalog, menyembunyikan tombol login/register di header, serta memblokir paksa seluruh akses rute perpustakaan (seperti /login, /register, /katalog, dll.) dan mengarahkannya kembali ke halaman Beranda (Home).

2. Panduan Troubleshooting API

  • Eror "Redirect URI Mismatch" saat Login Google: Periksa kembali seting **Authorized Redirect URIs** di Google Cloud Console. Pastikan tidak ada kesalahan ketik dan URL Callback harus menggunakan domain Supabase Anda: 
    https://anqopdxzdkpsmtxuultp.supabase.co/auth/v1/callback
  • Eror "401 Unauthorized" pada Cron Job / Webhook: Hal ini menandakan header token x-cron-secret tidak cocok. Periksa kembali dan pastikan string `CRON_SECRET` di **Supabase Secrets** sama persis dengan yang dimasukkan pada trigger cron atau GitHub Actions Secrets.
  • Tulisan "Hanya untuk pengujian" di Cloudflare Turnstile: Ini terjadi karena sistem masih mendeteksi site key pengujian. Daftarkan domain Anda di dashboard Turnstile Cloudflare, dapatkan site key produksi yang berawalan 0x4AAAAAA..., lalu daftarkan di dashboard hosting Pages Anda sebagai variabel VITE_TURNSTILE_SITE_KEY.
