Bab 1: Panduan Memulai & Sistem Desain Portal

Website Perpustakaan Digital & Kearsipan Kabupaten Purwakarta dirancang sebagai portal modern, hangat, dan berstandar dinas nasional yang terinspirasi dari sistem desain Elsevier dan New York Public Library.

1. Sistem Desain (Design System)

Palet Warna (Color Palette)

  • Warna Primer (Primary): Deep Navy (#1E3A5F atau #0c2f3d) - Memberikan kesan profesional, akademis, tepercaya, dan berwibawa.
  • Warna Sekunder: Light Gray (#F5F5F5) - Bersih dan minimalis sebagai pemisah konten secara visual.
  • Warna Aksen (Accent): Warm Beige (#C8A97E atau #c09440) - Memberikan atmosfer ruang baca perpustakaan yang hangat, nyaman, dan bersahabat.
  • Warna Latar Belakang (Background): Soft White (#FFFFFF / #f8fafc).
  • Sage Green: (#9DAD97) - Warna penyeimbang untuk aksen tenang dan detail visual.

Tipografi (Typography)

  • Judul Halaman (Headings): Playfair Display (Serif, anggun, formal, dan mencerminkan kewibawaan literatur).
  • Teks Utama (Body): Inter (Modern, bersih, tingkat keterbacaan tinggi di layar HP/Android).
  • Aksen Budaya: Noto Sans Sundanese (Digunakan untuk penulisan aksara Sunda pada detail ornamen visual khas daerah).

Prinsip Desain (Design Principles)

  • Minimalis, bersih, dan elegan dengan memanfaatkan whitespace secara seimbang.
  • Atmosfer membaca yang nyaman ("warm and cozy reading atmosphere").
  • Kesan akademis, tepercaya, dan ramah pengguna (user-friendly).
  • Animasi halus (smooth transitions) dan interaksi mikro (micro-interactions) untuk meningkatkan keterlibatan pengguna.
  • Layout berbasis kartu (card-based layout) dengan bayangan lembut (soft shadows) dan sudut melengkung di seluruh komponen.

2. Fitur Utama Sistem (Live Implementation)

Sistem Autentikasi & Anggota (Fully Integrated)

  • Real Supabase Auth: Sistem login, logout, dan pendaftaran anggota yang terintegrasi penuh secara real-time dengan cloud database Supabase.
  • Email Verification (SMTP Resend): Pengiriman kode OTP (One Time Password) dan magic link verifikasi melalui provider pihak ketiga Resend.com.
  • Premium Verification Flow: Halaman verifikasi khusus dengan UI Glassmorphism modern, memiliki hitung mundur cooldown pengiriman ulang OTP selama 60 detik, serta verifikasi kode aman 8-digit.
  • NIK Masking: Proteksi privasi secara otomatis menyensor data Nomor Induk Kependudukan (NIK) anggota di seluruh dashboard admin maupun profil user.

Katalog & Perpustakaan Digital

  • Katalog Buku Dinamis: Sistem pencarian, pengurutan, dan penyaringan kategori buku yang tersinkronisasi langsung dengan tabel database PostgreSQL.
  • Numbered Pagination: Sistem navigasi halaman bernomor profesional (1, 2, 3...) untuk menggantikan tombol "Muat Lebih Banyak" yang kurang ramah SEO dan menyulitkan pencarian halaman spesifik.
  • Manajemen Kategori: Dashboard admin canggih untuk mengelola kategori buku perpustakaan secara mudah dengan desain antarmuka yang efisien.

Konten & Artikel

  • Cinematic Media View: Tampilan galeri khusus untuk kategori "Media Mewarnai" dengan fitur unduhan PDF yang dioptimalkan agar file tidak rusak (anti-corrupt).
  • Dashboard Admin Terpadu: Content Management System (CMS) lengkap untuk mengelola Artikel berita, Buku, Kategori, Aset Media, Pengaduan, dan Data Anggota.

Bab 3: Arsitektur Keamanan: React + Supabase + Cloudflare Pages

Spesifikasi teknis arsitektur keamanan tingkat lanjut untuk menjaga integritas data transaksi dan perlindungan akses API.

1. Integritas Data (Data Integrity): Mengunci Kolom Sensitif

Jika mengandalkan validasi di sisi browser saja, peretas dengan mudah dapat membypass JavaScript lewat console. Oleh karena itu, kita menerapkan Server-Driven Immutability di level database.

Desain Skema SQL PostgreSQL (Supabase)

-- Tabel Berita/Artikel
CREATE TABLE public.articles (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    content TEXT NOT NULL,
    
    -- Immutable: Hanya boleh ditulis saat INSERT, haram di-UPDATE
    created_at TIMESTAMP WITH TIME ZONE DEFAULT now() NOT NULL,
    created_by TEXT NOT NULL,
    
    -- Server-controlled: Hanya dimodifikasi via trigger database
    status TEXT DEFAULT 'draft' NOT NULL,
    published_at TIMESTAMP WITH TIME ZONE,
    
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT now(),
    updated_by TEXT,
    
    CONSTRAINT valid_status CHECK (status IN ('draft', 'published', 'archived'))
);

-- Trigger: Mengisi published_at otomatis saat status berubah menjadi 'published'
CREATE OR REPLACE FUNCTION public.set_published_timestamp()
RETURNS TRIGGER AS $$
BEGIN
    IF NEW.status = 'published' AND OLD.status != 'published' THEN
        NEW.published_at = now();
    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trigger_set_published_timestamp
BEFORE UPDATE ON public.articles
FOR EACH ROW
EXECUTE FUNCTION public.set_published_timestamp();

-- Kebijakan RLS (Row Level Security) untuk kolom Immutable
CREATE POLICY "Created at immutable"
ON public.articles
FOR UPDATE
USING (auth.uid()::text = created_by)
WITH CHECK (
    created_at = OLD.created_at
    AND created_by = OLD.created_by
    AND (
        (NEW.status = 'published' AND OLD.status != 'published')
        OR (NEW.status = OLD.status)
    )
);

Implementasi Sisi Frontend (TypeScript)

Jangan pernah mengirim kolom immutable saat melakukan update agar tidak memicu pemblokiran RLS di level PostgreSQL:

// ✅ CARA YANG BENAR: Hanya kirim kolom yang boleh diubah
const saveArticle = async (article: Article) => {
  const { error } = await supabase
    .from('articles')
    .update({
      title: article.title,
      content: article.content
      // Kolom created_at, created_by, status tidak dikirim
    })
    .eq('id', article.id);

  if (error?.code === '42501') {
    console.error('Akses RLS ditolak: Kolom terkunci!');
  }
};

Middleware Validasi di Edge Function

Pemeriksaan immutable juga diperkuat di layer Supabase Edge Function:

// supabase/functions/update-article/index.ts
import { serve } from "https://deno.land/std@0.168.0/http/server.ts";
import { createClient } from "https://esm.sh/@supabase/supabase-js@2";

serve(async (req) => {
  if (req.method !== "PATCH") return new Response("Method not allowed", { status: 405 });
  const authHeader = req.headers.get("Authorization");
  if (!authHeader) return new Response("Unauthorized", { status: 401 });

  const supabase = createClient(
    Deno.env.get("SUPABASE_URL")!,
    Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")!
  );

  const { data: { user }, error: authError } = await supabase.auth.getUser(
    authHeader.replace("Bearer ", "")
  );
  if (authError || !user) return new Response("Unauthorized", { status: 401 });

  const { id, title, content } = await req.json();

  const { data: current, error: fetchError } = await supabase
    .from("articles")
    .select("*")
    .eq("id", id)
    .single();

  if (fetchError) return new Response("Not found", { status: 404 });
  if (current.created_by !== user.id) {
    return new Response("Unauthorized: Not the author", { status: 403 });
  }

  const allowedUpdate = {
    title: title || current.title,
    content: content || current.content,
    updated_at: new Date().toISOString(),
    updated_by: user.id
  };

  const { error } = await supabase.from("articles").update(allowedUpdate).eq("id", id);
  return new Response(JSON.stringify({ success: !error }), { status: error ? 400 : 200 });
});

2. Kontrol Akses (Access Control): RLS vs Middleware

Aspek Row-Level Security (RLS) Edge Middleware
Kecepatan Sangat cepat (filter di level query database). Ada sedikit latensi jaringan serverless.
Kompleksitas Logika Terbatas pada ekspresi SQL. Sangat fleksibel (TypeScript & Deno).
Audit Logs Harus diatur manual via trigger SQL. Dapat langsung dicatat ke log audit.
Risiko Bypass Sangat aman, dipaksa di level engine database. Bergantung pada keamanan kode API endpoint.

Rekomendasi Terbaik (Hybrid Approach): Gunakan RLS untuk penyaringan dasar kepemilikan baris data (misal: created_by = auth.uid()::text), dan gunakan Edge Function untuk otorisasi yang membutuhkan audit log atau verifikasi captcha.

Bab 4: Kumpulan SQL Migrasi Database & Perbaikan Auth

Semua query SQL berikut wajib dijalankan di SQL Editor Supabase agar sistem manajemen autentikasi dapat berfungsi tanpa kesalahan di server hosting produksi.

1. Trigger: Hapus Otomatis Auth User (trigger_handle_member_deleted)

Fungsi: Menghapus kredensial login di auth.users secara otomatis saat admin menghapus anggota dari tabel member, mencegah adanya email anggota tersangkut:

CREATE OR REPLACE FUNCTION public.handle_member_deleted()
RETURNS TRIGGER AS $$
BEGIN
  -- Hapus akun user di auth.users secara otomatis
  DELETE FROM auth.users WHERE id = OLD.id::uuid;
  RETURN OLD;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

DROP TRIGGER IF EXISTS trigger_handle_member_deleted ON public.members;
CREATE TRIGGER trigger_handle_member_deleted
  AFTER DELETE ON public.members
  FOR EACH ROW
  EXECUTE FUNCTION public.handle_member_deleted();

2. RPC: Hapus Bersih User Berdasarkan Email (force_delete_user_by_email)

Fungsi: Fungsi pembersihan darurat untuk menghapus total data pengguna (Admin, Member, Transaksi Pinjam, Antrian, dan Autentikasi Auth) hanya menggunakan parameter email:

CREATE OR REPLACE FUNCTION public.force_delete_user_by_email(target_email text)
RETURNS void
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, auth
AS $$
DECLARE
  target_user_id uuid;
BEGIN
  SELECT id INTO target_user_id FROM auth.users WHERE lower(email) = lower(target_email);
  
  IF target_user_id IS NOT NULL THEN
    DELETE FROM public.borrows WHERE "memberId" = target_user_id::text;
    DELETE FROM public.queue WHERE "memberId" = target_user_id::text;
    DELETE FROM public.admins WHERE id = target_user_id;
    DELETE FROM public.members WHERE id = target_user_id::text;
    DELETE FROM auth.users WHERE id = target_user_id;
  END IF;
END;
$$;

-- Contoh penggunaan:
-- SELECT public.force_delete_user_by_email('email_warga@gmail.com');

3. RPC: Pembuatan Akun Admin Auto-Confirm dengan Sinkronisasi Identitas

Fungsi: Membuat admin baru langsung aktif (Auto-Confirm) sekaligus mendaftarkan data ke tabel auth.identities agar Supabase GoTrue Auth tidak mengembalikan error status 500:

CREATE OR REPLACE FUNCTION public.create_new_admin_user(
  admin_email text, admin_password text, admin_name text, admin_role text, avatar_col text
)
RETURNS uuid LANGUAGE plpgsql SECURITY DEFINER
SET search_path = public, auth, extensions
AS $$
DECLARE
  new_user_id uuid;
  encrypted_pw text;
BEGIN
  IF NOT public.is_super_admin_from_admins() THEN
    RAISE EXCEPTION 'Akses ditolak.';
  END IF;

  new_user_id := gen_random_uuid();
  encrypted_pw := crypt(admin_password, gen_salt('bf', 10));

  -- Insert ke auth.users
  INSERT INTO auth.users (id, instance_id, aud, role, email, encrypted_password, email_confirmed_at, raw_app_meta_data, raw_user_meta_data, created_at, updated_at, is_super_admin, is_anonymous)
  VALUES (new_user_id, '00000000-0000-0000-0000-000000000000', 'authenticated', 'authenticated', lower(admin_email), encrypted_pw, now(), '{"provider":"email","providers":["email"]}', jsonb_build_object('namaLengkap', admin_name), now(), now(), false, false);

  -- Insert ke auth.identities (Pencegah Error 500)
  INSERT INTO auth.identities (id, provider_id, user_id, identity_data, provider, last_sign_in_at, created_at, updated_at)
  VALUES (new_user_id, new_user_id::text, new_user_id, jsonb_build_object('sub', new_user_id::text, 'email', lower(admin_email), 'email_verified', true, 'email_verified_at', now()), 'email', now(), now(), now());

  -- Insert ke public.admins
  INSERT INTO public.admins (id, nama_lengkap, email, password_hash, role, tanggal_dibuat, avatar_color)
  VALUES (new_user_id, admin_name, lower(admin_email), encrypted_pw, admin_role, (EXTRACT(DAY FROM now())::text || ' ' || 'Juni' || ' ' || EXTRACT(YEAR FROM now())::text), avatar_col);

  RETURN new_user_id;
END;
$$;

REVOKE ALL ON FUNCTION public.create_new_admin_user(text, text, text, text, text) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION public.create_new_admin_user(text, text, text, text, text) TO authenticated;

4. RPC: Pembaru Sandi Admin Terenkripsi (update_admin_password)

Fungsi: Mengupdate sandi admin secara terenkripsi baik di tabel profil public.admins maupun tabel kredensial auth Supabase:

CREATE OR REPLACE FUNCTION public.update_admin_password(
  target_user_id uuid,
  new_password text
)
RETURNS boolean
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public, auth, extensions
AS $$
DECLARE
  encrypted_pw text;
BEGIN
  IF NOT (public.is_super_admin_from_admins() OR auth.uid() = target_user_id) THEN
    RAISE EXCEPTION 'Akses ditolak.';
  END IF;

  IF new_password IS NULL OR length(new_password) < 6 THEN
    RAISE EXCEPTION 'Password minimal 6 karakter.';
  END IF;

  encrypted_pw := crypt(new_password, gen_salt('bf', 10));

  UPDATE auth.users SET encrypted_password = encrypted_pw, updated_at = now() WHERE id = target_user_id;
  UPDATE public.admins SET password_hash = encrypted_pw WHERE id = target_user_id;

  RETURN true;
END;
$$;

REVOKE ALL ON FUNCTION public.update_admin_password(uuid, text) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION public.update_admin_password(uuid, text) TO authenticated;

5. Workaround React Strict Mode Login Dobel (AuthCallback.tsx)

Dalam mode development, React 18 memicu useEffect dua kali secara beruntun. Hal ini menyebabkan pertukaran token Google OAuth (exchangeCodeForSession) terkirim dua kali, memicu error "Link kedaluwarsa" pada render kedua karena token sekali pakai tersebut telah ditukarkan pada render pertama.

Solusi: Kode src/pages/AuthCallback.tsx telah dimodifikasi untuk memeriksa ketersediaan sesi aktif via supabase.auth.getSession() terlebih dahulu. Jika session sudah terbentuk, proses penukaran token yang kedua langsung dilewati (bypass) dan user diarahkan ke dashboard.

Bab 5: Panduan Serah Terima Pengembang (Developer Handover)

Panduan bagi programmer baru untuk memahami arsitektur berkas src/services/ dan src/pages/ secara cepat dan efisien.

1. Alur Pembacaan Cepat Kode Sumber

  1. Buka file src/App.tsx sebagai peta rute navigasi dan pelindung rute login.
  2. Pelajari modul layanan sirkulasi data di direktori src/services/ untuk interaksi dengan Supabase.
  3. Telusuri kode halaman portal user di src/pages/ dan panel administrator di src/pages/admin/.

2. Nilai Batasan dan Konstanta Operasional (Hardcoded Limits)

  • Batas Halaman Artikel Berita: Dibatasi maksimal 10 item per muatan halaman (PAGE_SIZE = 10).
  • Batas Katalog Buku: Dibatasi maksimal 12 buku per muatan halaman (BOOKS_PER_PAGE = 12).
  • Batas Waktu Cooldown OTP: Pemicu kirim ulang email verifikasi OTP dikunci minimal selang waktu 60 detik.
  • Keamanan Sesi Login Admin: Sesi JWT aktif maksimal selama 12 jam (ADMIN_SESSION_TTL = 12 * 60 * 60 * 1000 ms). Jika sandi salah dimasukkan 5 kali berturut-turut, akun dikunci (lockout) selama 15 menit.

3. Dokumentasi Ringkas Berkas Modul Layanan (Services)

  • authService.ts & supabaseAuthService.ts: Mengatur pemeliharaan session login lokal, cookie keamanan, lockout, update profil member, dan pendaftaran ke Supabase Auth.
  • bookService.ts: Mengatur fungsi sirkulasi peminjaman buku, sinkronisasi stok buku fisik di database, wishlist, rating, dan antrean otomatis buku habis.
  • dataService.ts: Mengelola CMS artikel berita, pencarian kata kunci, kategori, dan sinkronisasi data cloud ke penyimpanan lokal cache browser.
  • settingsService.ts: Memuat pengaturan portal statis instansi (PPID, Struktur, Jadwal) secara paralel saat loading awal website.
  • db.ts: Wrapper untuk local storage browser yang bertindak sebagai database cadangan lokal.
  • imageUtils.ts & storageService.ts: Utilitas upload aset gambar, konversi tipe file, dan bucket policy Supabase Storage.

4. Dokumentasi Berkas Halaman (Pages)

Halaman Utama & Portal Warga (User Pages)

  • Home.tsx: Halaman landing page utama dengan galeri cinematic, review buku populer, dan link internal.
  • KatalogBuku.tsx: Antarmuka eksplorasi buku digital dengan pencarian pintar, filter kategori, dan tombol aksi peminjaman.
  • BlogList.tsx & ArticleDetail.tsx: Daftar berita dan pembaca artikel dinamis yang dilengkapi tombol bagikan dan unduhan file lampiran.
  • LaporWarga.tsx: Form pengaduan publik yang terintegrasi dengan Telegram Bot API untuk notifikasi instan admin.
  • AuthVerifyCode.tsx: Input kode OTP dengan proteksi rute session guard dan visual Glassmorphism.

Halaman Panel Administrator (Admin Pages)

  • AdminDashboard.tsx: Panel ringkasan data statistik sistem (total transaksi, buku dipinjam, member aktif).
  • ArticleEditor.tsx & BookEditor.tsx: Halaman editor interaktif untuk input/edit artikel (dilengkapi caption style) dan katalog buku baru.
  • ManageBorrows.tsx: Panel pengelolaan status sirkulasi buku (konfirmasi pinjam, buku dikembalikan, hitung denda telat).
  • ManageMembers.tsx: Fitur penghapusan anggota secara aman yang otomatis memicu pembersihan user di Supabase Auth.

Bab 6: Panduan Modul Mandiri (Standalone Booking Micro-Frontend)

Direktori standalone-booking/ menyimpan versi enkapsulasi mandiri (micro-frontend) dari modul pendaftaran booking restorasi arsip warga.

1. Keuntungan Penggunaan Modul Mandiri

  • Performa Optimal: Bundle kompilasi sangat ringan karena tidak memuat visual dan logika modul utama perpustakaan digital.
  • Kemandirian Sistem: Jika website utama WordPress mengalami crash atau pemeliharaan server, portal booking arsip tetap aktif melayani masyarakat.
  • Pusat Konfigurasi Tunggal: Parameter alamat web utama, warna, kontak, dan logo diatur di satu file pusat.

2. Konfigurasi Terpusat (src/config/bookingConfig.ts)

Sesuaikan file branding berikut sebelum meng-compile aplikasi:

export const BOOKING_CONFIG = {
  // 1. BRANDING & IDENTITAS
  BRAND: {
    NAME: 'Disipusda Purwakarta',
    SHORT_NAME: 'Disipusda',
    SLOGAN: 'Layanan Booking Enkapsulasi & Pemeliharaan Arsip',
    LOGO: logoUtama,
  },

  // 2. REDIRECT TOMBOL KEMBALI
  MAIN_WEBSITE_URL: import.meta.env.VITE_MAIN_WEBSITE_URL || 'https://disipusda.purwakartakab.go.id',

  // 3. KETERANGAN FOOTER
  FOOTER: {
    ADDRESS: 'Jl. Veteran No. 1, Ciseureuh, Purwakarta',
    TELEPHONE: '+62 812-3456-7890',
    EMAIL: 'arsip@disipusda.purwakarta.go.id',
  }
};

3. Langkah Menjalankan dan Melakukan Deployment

Menjalankan di Lokal (Development)

cd standalone-booking
npm install
cp .env.example .env
npm run dev

Deploy ke Server Subdomain (Hosting)

  1. Jalankan proses build produksi di folder standalone-booking/: 
    npm run build
  2. Unggah isi folder hasil kompilasi dist/ ke subdomain hosting Anda (contoh: booking.purwakartakab.go.id).
  3. Pasang Iframe pada website utama WordPress Anda untuk mengintegrasikan widget booking secara langsung: 
    <iframe 
  src="https://booking.purwakartakab.go.id" 
  width="100%" 
  height="950px" 
  style="border: none; overflow: hidden;"
  scrolling="no">
</iframe>
